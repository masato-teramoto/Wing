# ゲート記録 format_version 2

`gate-record.md` は初回に phase（intake / steering / feature / requirements / design / docs / tasks）と created_at を埋めて使う。以後は既存バイト列を変更せず、ファイル末尾へブロックを追加する。フロントマターに updated_at を追加しない。最終日時は末尾の実行・人間回答の日時から導く。

## 実行ブロック

検査役は1実行ブロックを inspection_path（`.aidd/.engine/<実行キー>.inspection.md`）に書き、ゲート記録へは直接書かない。L3 の scope-check が内容を確認してゲート記録の末尾へ1回だけ追記し、検査対象を draft/review → review に遷移させる。

毎回 `## 実行` と `### 指摘` を連続して追記する。回数はスコープごとに 1 から連番。スコープは `phase` / `feature:<name>` / `cross`。この版から、Feature 方式の selection 単位の `cross:<name>`（横断確認。確認行を書き status を変えない）と `phase:<name>`（tasks の selection 承認。承認行を書き status を変える）を含みうる（`<name>` は選択 feature 名）。列は変わらない。指摘 0 件でも指摘表の見出し・区切りは必要で、架空の 0 件行を入れない。

| セクション | 固定列 |
|---|---|
| 実行 | スコープ / 回数 / 実行日時 / 実行した層 / 対象成果物 / 原本SHA256 / 指摘件数 |
| 指摘 | # / 観点 / 種類 / 重大度 / 同一性キー / 節ハッシュ / 対象箇所 / 対象の語 / 要約 / 指摘内容 / 修正案 / 推奨 / 確かめ役 / 判断 / 理由 |
| 差戻し先候補（任意） | 指摘番号 / 宛先 / 理由 |
| 除外（任意） | 観点 / 対象箇所 / 要約 / 除外の出典 |

### 検査役が inspection_path に書く形

検査役は重大度・同一性キー・節ハッシュを書かない。指摘表は次の 12 列で書く。

```
## 実行
| スコープ | 回数 | 実行日時 | 実行した層 | 対象成果物 | 原本SHA256 | 指摘件数 |
（1 行）

### 指摘
| # | 観点 | 種類 | 対象箇所 | 対象の語 | 要約 | 指摘内容 | 修正案 | 推奨 | 確かめ役 | 判断 | 理由 |

### 差戻し先候補   （任意）
| 指摘番号 | 宛先 | 理由 |

### 除外   （任意。前提に当たるため出さなかった指摘）
| 観点 | 対象箇所 | 要約 | 除外の出典 |
```

L3 の scope-check がこれを確かめ、種類から重大度、種類・対象箇所・対象の語から同一性キー、対象箇所の節から節ハッシュを埋めて 15 列に直す。同一性キーが同じ指摘は 1 件にまとめてから記録の末尾へ追記する。新しい検査は旧形式の 6 列（`# / 観点 / 対象箇所 / 指摘内容 / 判断 / 理由`）で書かない。

実行表は 1 行。対象成果物は正規化した案件相対パスの JSON 配列、原本SHA256 はパス→ハッシュの JSON オブジェクト。L3 のスナップショット値を転記する。本文と status/updated_at 以外のメタデータがハッシュ対象。実行した層は実際に実施した `①` / `②` / `①②`。形式検査を行わない横断検査を `①②` と記録しない。

指摘番号は実行内で 1 から連番。観点・対象箇所・指摘内容は必須（種類を持つ形では種類・要約も必須）。判断・理由は空欄。

| 列 | 中身 |
|---|---|
| 種類 | `業務の欠落・矛盾` / `業務のあいまい・不足` / `工程・文書の分担` / `文書間の参照` / `出典・根拠` / `書式` のどれか。機械検査の指摘は観点（機械検査の名前）で決まる（format-conformance → 書式 または 文書間の参照、revision-diff-validity・sequence-consistency → 文書間の参照、dependency-cycle-detection → 業務の欠落・矛盾）。それ以外の種類は L3 が受け付けない |
| 重大度 | L3 が種類から決める（業務の欠落・矛盾 → `重大`、業務のあいまい・不足 → `要判断`、ほか → `軽微`）。種類と食い違う値は受け付けない |
| 同一性キー・節ハッシュ | L3 が埋める 16 桁の英小文字・数字。節が決まらなければ節ハッシュは `-` |
| 対象箇所 | `<案件相対パス> § <節見出し> / <ID>`。複数箇所は代表 1 か所＋「ほか n か所」 |
| 対象の語 | 指摘している対象を表す短い語（例：`貸出期間の上限`、`AC-3`） |
| 要約 | 60 字以内。結論を先に、「何が・どこで」を 1 文で |
| 指摘内容 | 根拠・引用・出典。機械指摘は本文のまま |
| 修正案・推奨・確かめ役 | 無いときは `-`。推奨は `修正：理由` / `差戻し：理由` / `対応せず進める：理由` / `質問：理由` のどれか。確かめ役は `確認済み` か `種類を変更：<元> → <新>：<理由>` |

除外の出典は次のどれか。L3 は出典が実在することを確かめ、無い出典の除外は受け付けない。

| 出典 | 意味 |
|---|---|
| `rule:<境界の id>` | 指摘の共通ルールの工程の境界（`B-01`〜`B-04`）、または `rule:TBD`（`TBD（<工程> で確定）` と書かれた事項） |
| `answer:<確定回答の key>` | 人が作成中の質問に答えて確定した回答 |
| `learned:<phase> <scope> <回数>-<番号>` | 同じ工程で、人が「今後も同じ扱い」とした却下 |
| `verify:<理由>` | 確かめ役が、実在しない・取り違え・重複と判断した指摘 |
| `unchecked:<理由>` | 形式不備で意味検査から外した節（その対象は意味検査が未完了として扱い、承認を止める） |

指摘件数には当該実行で検出した件数だけを書く。以前の未解消指摘は、その元のスコープ・回数・番号で別途参照する。

各層はその層に指定された観点をすべて実施した場合だけ記録する。指摘0件・指摘受容・
過去回の実施で今回の未実施層を補わない。必要な層と承認条件は L3 status-protocol.md が定める。

## 人間回答のブロック

人間の回答を得たホストだけが、L3 の記録補助で追記する。検査 agent は作らない。指摘の元の表へ判断を書き戻さない。
ただし scope-check の直後に、L3 が判断者・確認者 `system（自動）` として判断・解消のブロックを追記することがある（下記）。

| セクション | 固定列 |
|---|---|
| 判断 | スコープ / 回数 / 指摘番号 / 判断 / 理由 / 判断者 / 日時 / 却下区分 / 今後も同じ扱い / 推奨の採用 |
| 解消 | スコープ / 回数 / 指摘番号 / 再検査スコープ / 再検査回数 / 確認者 / 日時 |
| 承認 | スコープ / 回数 / 対象成果物 / 承認者 / 承認日時 / 原本SHA256 |
| 確認（横断検査） | スコープ / 回数 / 確認者 / 日時 / 原本SHA256 |
| 残件 | スコープ / 回数 / 指摘番号 / 判断 / 理由 / 承認スコープ / 承認回数 |

判断は `修正` / `差戻し` / `対応せず進める` / `未対応`。後二者は理由必須。却下区分は `対応せず進める` のときだけ `指摘の誤り` / `対象外` / `後で決める` / `解釈で対応` のどれかを書け、今後も同じ扱い（`はい`）は対象外・後で決めるにだけ付けられる。推奨の採用は `採用` / `不採用` / 空欄。

`system（自動）` が記録するのは次だけである。前回 `対応せず進める` / `未対応` とした同じ指摘（同一性キーが同じ）で節ハッシュが変わっていないものへの同じ判断、修正案のある軽微への `修正`（横断・tasks 全体・実装の検査を除く）、前回 `修正` / `差戻し` とした指摘が再検査で出ず節が変わったときの解消。

`未対応` は残件として同じスコープの以後のレビューに持ち越して示し、承認・確認の時点で残っていた `未対応` / `対応せず進める` は `残件` ブロックに記す（alpha2 の「承認時の残件」）。解消には、同じスコープ、または対象を包含する全件スコープ（`cross` ⊇ `cross:<name>`、`phase` ⊇ `phase:<name>`）の後続検査回と確認者（人間、または `system（自動）`）を記録する。逆向き（全件スコープの指摘を selection の回で解消すること）は認めない。承認は対象パス・当該検査回・ハッシュの完全一致で照合する。横断の確認は対象のハッシュ辞書を記し、成果物 status を変更しない。

## 共通書式

表は必ず両端の `|`、固定の列数、`---` の区切り行を持つ。セル内の `&` / `<` / `>` は HTML エスケープし、`|` は `&#124;`、改行は `&#10;` とする。日時はタイムゾーン付き ISO 8601。テンプレートのままの値や空の承認者で完了にしない。

旧形式の 6 列の指摘表・7 列の判断表もそのまま読める（種類を持たない指摘は人に出す）。旧形式を v2 と見せかけて読み飛ばさない。旧ファイルは証跡として保持し、明示的な移行と再確認を行う。
