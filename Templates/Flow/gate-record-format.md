# ゲート記録 format_version 2

`gate-record.md` は初回に phase（intake / steering / feature / requirements / design / docs / tasks）と created_at を埋めて使う。以後は既存バイト列を変更せず、ファイル末尾へブロックを追加する。フロントマターに updated_at を追加しない。最終日時は末尾の実行・人間回答の日時から導く。

## 実行ブロック

検査役は1実行ブロックを inspection_path（`.aidd/.engine/<実行キー>.inspection.md`）に書き、ゲート記録へは直接書かない。L3 の scope-check が内容を確認してゲート記録の末尾へ1回だけ追記し、検査対象を draft/review → review に遷移させる。

毎回 `## 実行` と `### 指摘` を連続して追記する。回数はスコープごとに 1 から連番。スコープは `phase` / `feature:<name>` / `cross`。指摘 0 件でも指摘表の見出し・区切りは必要で、架空の 0 件行を入れない。

| セクション | 固定列 |
|---|---|
| 実行 | スコープ / 回数 / 実行日時 / 実行した層 / 対象成果物 / 原本SHA256 / 指摘件数 |
| 指摘 | # / 観点 / 対象箇所 / 指摘内容 / 判断 / 理由 |
| 差戻し先候補（任意） | 指摘番号 / 宛先 / 理由 |

実行表は 1 行。対象成果物は正規化した案件相対パスの JSON 配列、原本SHA256 はパス→ハッシュの JSON オブジェクト。L3 のスナップショット値を転記する。本文と status/updated_at 以外のメタデータがハッシュ対象。実行した層は実際に実施した `①` / `②` / `①②`。形式検査を行わない横断検査を `①②` と記録しない。

指摘番号は実行内で 1 から連番。観点・対象箇所・指摘内容は必須。判断・理由は空欄。指摘件数には当該実行で検出した件数だけを書く。以前の未解消指摘は、その元のスコープ・回数・番号で別途参照する。

各層はその層に指定された観点をすべて実施した場合だけ記録する。指摘0件・指摘受容・
過去回の実施で今回の未実施層を補わない。必要な層と承認条件は L3 status-protocol.md が定める。

## 人間回答のブロック

人間の回答を得たホストだけが、L3 の記録補助で追記する。検査 agent は作らない。指摘の元の表へ判断を書き戻さない。

| セクション | 固定列 |
|---|---|
| 判断 | スコープ / 回数 / 指摘番号 / 判断 / 理由 / 判断者 / 日時 |
| 解消 | スコープ / 回数 / 指摘番号 / 再検査スコープ / 再検査回数 / 確認者 / 日時 |
| 承認 | スコープ / 回数 / 対象成果物 / 承認者 / 承認日時 / 原本SHA256 |
| 確認（横断検査） | スコープ / 回数 / 確認者 / 日時 / 原本SHA256 |
| 残件 | スコープ / 回数 / 指摘番号 / 判断 / 理由 / 承認スコープ / 承認回数 |

判断は `修正` / `差戻し` / `対応せず進める` / `未対応`。後二者は理由必須。`未対応` は残件として同じスコープの以後のレビューに持ち越して示し、承認・確認の時点で残っていた `未対応` / `対応せず進める` は `残件` ブロックに記す（alpha2 の「承認時の残件」）。解消には同じスコープの後続検査回と人間の確認を記録する。承認は対象パス・当該検査回・ハッシュの完全一致で照合する。横断の確認は対象のハッシュ辞書を記し、成果物 status を変更しない。

## 共通書式

表は必ず両端の `|`、固定の列数、`---` の区切り行を持つ。セル内の `&` / `<` / `>` は HTML エスケープし、`|` は `&#124;`、改行は `&#10;` とする。日時はタイムゾーン付き ISO 8601。テンプレートのままの値や空の承認者で完了にしない。

旧形式を v2 と見せかけて読み飛ばさない。旧ファイルは証跡として保持し、明示的な移行と再確認を行う。
