## 概要

RFP 中の制約・非機能要求の記述に、法令・規制コンプライアンス（個人情報保護法、業種別規制、
アクセシビリティ規制等）に関わる要求が含まれていないかを検出し、それが要求一覧に反映されて
いるかを確認する。呼び出し元は制約/非機能の行を対象として指定する。

## 入力

| 項目 | 内容 | 指定例 |
|---|---|---|
| 対象 | 検査する要求一覧の行 | `.aidd/requirement-list.md` の制約/非機能の行 |
| 根拠 | 法令要求の手がかりを探す元 | `.aidd/rfp/**` |

## 手順

1. `根拠`（RFP）を読み、業種・取扱データ・対象国/地域から推定される法令コンプライアンス要求の
   手がかり（個人情報、決済情報、医療情報、越境データ移転等への言及）を洗い出す。
2. `対象`（要求一覧の制約/非機能行）に、その法令コンプライアンス要求が要求として反映されて
   いるかを確認する。
3. RFP に法令コンプライアンスへの言及があるにもかかわらず、要求一覧に対応する要求が無い場合を
   検出する。
4. 逆方向に、`対象` の各行のうち個人情報保護・業界規制等に基づくと推測される要求（例: 「個人情報を
   暗号化して保存する」「監査ログを5年保持する」）について、その根拠が RFP 中の法令・規制への言及として
   明示されておらず、要求一覧の分類・記述からも法令・規制に基づく要求だと読み取れない行を指摘する。
5. gap-proposal 等で既に同一趣旨の提案がある箇所は重ねて指摘しない。

## 出力の形

```
{ id, location, finding, is_rollback_candidate }
```

| フィールド | 内容 |
|---|---|
| `id` | この Skill 内で一意な通し番号 |
| `location` | RFP中の該当箇所、または要求一覧側で欠落している箇所 |
| `finding` | 検出した法令コンプライアンス要求の欠落事実（例: 「RFPに明示された法令対応要求が要求一覧へ転記されていない。出典箇所を確認する」） |
| `is_rollback_candidate` | 通常 `false`（Phase 1内で要求を追記すれば解消できるため） |

## 禁止

- 対象成果物を書き換えない（法令要求を自動で追記しない）
- 合否を出さない
- 具体的な法令名・条文の断定はしない（該当し得る旨と要求としての反映有無の指摘に留める）

RFPに明示されない法令適用の推測は欠落事実と混ぜず、確認が必要な提案として返す。具体的な法令の適用・適法性をこの検査で確定しない。
