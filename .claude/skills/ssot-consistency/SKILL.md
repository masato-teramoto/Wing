# ssot-consistency（① / ② 二重定義・参照切れ検出）

> 層 **① / ②**。呼び出し元は各フェーズの `<Phase>-Check-Subagent`。

同じ事実が 2 か所に書かれていないか（**二重定義**）と、参照が受け手に届いているか（**参照切れ・受け手不在**）を見る。

---

## 入力（呼び出し時に必ず指定する項目）

| 項目 | 内容 |
|---|---|
| `対象成果物` | 検査するファイル群（複数可） |
| `検査する事実の種類` | 何を「同じ事実」とみなすか |
| `SSoT の所在` | その事実をどのファイル・どのセクションが所有すべきか。所有者が未定なら「未定（どちらが正かを人間に確認する）」 |
| `検査の型` | `二重定義` / `参照切れ` / `受け手不在` / それらの組み合わせ |
| `報告単位` | 何を 1 件として報告するか |

### 呼び出し例

| 指定項目 | Phase 2 での値 | Phase 4 横断での値 | Phase 5 横断での値 |
|---|---|---|---|
| 対象成果物 | `steering/` 7ファイル | `specs/*/requirements.md` | `specs/*/design.md` |
| 検査する事実の種類 | プロジェクト方針の各記述 | Dependencies / Adjacent の期待 | API / Event / Data Contracts、業務コード・区分値・エンティティ |
| SSoT の所在 | 7ファイルの記述分担 | `feature-list.md` の `依存` 列 | 契約を公開している側の feature の design |
| 検査の型 | 二重定義 + 参照切れ | 受け手不在 | 二重定義 |
| 報告単位 | 重複している記述の対 | 受け手のいない期待 | 別形状に定義されている要素 |

---

## 手順

### 二重定義

1. `対象成果物` から `検査する事実の種類` に該当する記述を列挙する。
2. **同じ事実を述べている記述の対**を探す。単語の一致ではなく、述べている内容が同一かで判定する。
3. 対が見つかったら次を報告する。
   - 記述の所在（両方）
   - `SSoT の所在` に照らして、**どちらが所有すべきか**
   - 両者が **同一の内容か、食い違っているか**（食い違いは二重定義より重い事実なので必ず書き分ける）
4. `SSoT の所在` が「未定」の場合、**どちらが正かを推測で決めない。** 両形状を並べて人間に確認を求める指摘として出す。

### 参照切れ

1. 「○○を参照」「`XXX.md` を参照」といった参照表現を列挙する。
2. 参照先が **存在するか**、存在しても **空でないか**を確認する。
3. 参照先が存在しない、または参照先に該当記述が無い場合に報告する。

### 受け手不在

1. `対象成果物` から「他者に期待している責務」を列挙する（依存・隣接・前提として宣言されているもの）。
2. 期待の**受け手側**の成果物を読み、その責務が **受け手のスコープ内に存在するか**を確認する。
3. 受け手側に存在しない期待を報告する。受け手のファイルが未作成の場合は、**欠落と断定せず**「未作成のため判定不能」として区別する。

---

## スコープの仕分け

**未作成を欠落と誤判定しうる項目は、横断スコープでのみ実行する。** 片側だけで判定できる部分は分解して成果物単位スコープに前倒しする。

| 判定 | スコープ |
|---|---|
| その成果物内、または上流の `approved` 成果物との突合で完結する | **成果物単位** |
| 他 feature の成果物が揃っていないと判定できない | **横断** |

**同じ項目を両スコープで実行しない。**

---

## 禁止

- 対象成果物を修正しない。
- 合否を出さない。重大度を付けない。
- どちらが正かを推測で決めない（`SSoT の所在` の指定が無い場合は人間に確認を求める指摘として出す）。
- 未作成のファイルを欠落として報告しない（「判定不能」と区別する）。
- 意図的な引用（上位方針を下位が「準拠」として引く記述）を二重定義として報告しない。二重定義は **同じ事実の定義が 2 か所にある**場合を指す。
