# gate-report（① / ② の結果出力）

> 呼び出し元は各フェーズの `<Phase>-Check-Subagent`。

ゲート記録は **③ 人間レビューが承認の可否を判断するための材料**である。**それ自体は合否を含まない。**
構造の正は `Templates/Flow/gate-record.md` である。**本 Skill に項目を書き写さない。**

---

## 入力（呼び出し時に必ず指定する項目）

| 項目 | 内容 |
|---|---|
| `フェーズ` | Phase 番号とフェーズ名 |
| `ゲート記録パス` | `.aidd/gates/phase-<N>-<名>.md` |
| `スコープ` | `成果物単位（<feature 名 / 成果物名>）` / `横断` |
| `対象成果物` | 検査したファイルの一覧 |
| `実行した層` | `①` / `① / ②`（② に進まなかった場合は `①` のみ） |
| `指摘一覧` | 各共通 Skill が返した指摘。1 件ごとに 層・対象箇所・指摘内容 |
| `差戻し先候補` | 上流の不備が疑われる場合の戻し先。無ければ「なし」 |

---

## 手順

1. `ゲート記録パス` の存在を確認する。
   - **無い場合**: `Templates/Flow/gate-record.md` をコピーし、フロントマターの `phase` を `フェーズ` で埋め、テンプレートのスロット行（`<GATE_RUN_SCOPE_N>` のように山括弧の大文字項目だけで構成された表の行）を削除して初期化する。
   - **ある場合**: 全文を読む。**既存の記述を一切変更しない。**
2. `スコープ` ごとの **実行回数**を数える。既存の「実行履歴」から同じ `スコープ` の行数を数え、その次の番号を使う。
3. 「実行履歴」に 1 行追記する。`指摘件数` は **当該実行で検出した件数**のみを書く（前回からの残件を含めない）。
4. 「指摘」セクションへ追記する。
   - `スコープ` が成果物単位なら、**対象 feature / 成果物名の見出しの下**に追記する。見出しが無ければ新設する。
   - `スコープ` が横断なら、**`### 【横断】` の見出しの下**に追記する。feature 別セクションに混ぜない。
   - 各行に `回数`（Step 2 の値）を入れ、どの実行で出た指摘かを追跡可能にする。
5. `差戻し先候補` がある場合、それを **指摘として** 記述する。**「差戻し」セクションには書かない。**
   - 「差戻し」セクションは、③ が差戻しを決めて実際に status を引き下げたときに記録する欄である。
   - 候補の提示は「上流の○○に不備がある可能性がある」という指摘に留める。**戻すかどうかを決めてはならない。**
6. フロントマターの `updated_at` を ISO 8601（オフセット付き）で更新する。
7. 追記が完了したことを呼び出し元へ返す。**この時点で初めて**、呼び出し元のサブエージェントが対象成果物を `draft` → `review` へ遷移させる。

---

## 指摘 1 件に書くこと

| 列 | 記入者 | 内容 |
|---|---|---|
| `#` | ゲート | 当該セクション内の連番 |
| `回数` | ゲート | 当該スコープで何回目の実行か |
| `層` | ゲート | `①` / `②`（③ の観点は人間が追記する） |
| `対象箇所` / `対象 feature` | ゲート | ファイル / セクション / 行 |
| `指摘内容` | ゲート | 何が期待と異なるかの事実 |
| `判断` | **③ の人間**（転記はオーケストレータ） | **空欄のまま出力する** |
| `理由` | **③ の人間**（転記はオーケストレータ） | **空欄のまま出力する** |

---

## 呼び出し元へ返す要約

ゲート記録への追記とは別に、③ へ提示するための要約を呼び出し元へ返す。

- 実行したスコープと回数、実行した層
- 当該実行で検出した指摘の件数と、指摘の一覧
- ② に進まなかった場合は **その事実と理由**（① で形式の不備を検出したため）
- `差戻し先候補` があればその内容

**要約に合否・推奨・優先順位を含めない。**

---

## 禁止

- **合否を出さない。** 「問題なし」「合格」「このまま進めて問題ない」と書かない。
- **重大度・優先度の区分を付けない。** すべての指摘を対等に並べる。優先順位付けは指摘内容を読んだ人間が行う。
- **`判断` 列・`理由` 列・「承認」セクションを埋めない。** ③ の人間が判断し、**オーケストレータが聞き取って転記する**欄である。空欄のまま出力する。
- **既存の記録を上書き・削除・要約しない。** 追記のみ。再ゲート・差戻しによる再実行は履歴として積む。
- ゲート記録に `status` を持たせない。
- 指摘がゼロの場合も **実行履歴には行を追記する**（実行した事実を残す）。指摘がゼロであることを承認の根拠として書かない。
- 対象成果物を修正しない。
