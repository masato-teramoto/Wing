# format-conformance（① 機械チェック）

> 層 **①**。呼び出し元は各フェーズの `<Phase>-Check-Subagent`。

**テンプレート構造の正は実行時に読む `Templates/` である。** 本 Skill に構造や項目名を書き写さない（テンプレートが増減しても Skill を直さずに済むようにするため）。

---

## 入力（呼び出し時に必ず指定する項目）

| 項目 | 内容 | 指定例 |
|---|---|---|
| `対象パス` | 検査する成果物のパス（複数可） | `specs/order-entry/requirements.md` |
| `テンプレパス` | 構造の正とするテンプレート | `Templates/specs/_template/requirements.md` |
| `ID 書式` | 当該成果物で使う ID の書式。無ければ「なし」 | 要件ID = 数値のみ（`1`, `1.1`） |
| `追加の存在検査` | フェーズ固有に存在だけを確認する項目。無ければ「なし」 | 各タスクに `_Requirements:` と観測可能な完了条件が 1 行以上 |
| `報告単位` | 指摘を並べる粒度 | ファイル × セクション |

**指定が無い項目を推測で補わない。** 不足していれば呼び出し元へ確認を返す。

---

## 手順

1. `テンプレパス` を読み、**見出し構造（`#`〜`####`）**と**フロントマターのキー集合**を抽出する。
2. `対象パス` を読み、同じ抽出を行う。
3. 次を突き合わせて指摘を作る。

| 検査 | 指摘にする条件 | 指摘にしない条件 |
|---|---|---|
| **必須セクションの欠落** | テンプレートに存在し対象に無い見出し | テンプレートが「任意」「必要時」「省略可」「不要なら削除してよい」と明記している見出し |
| **フロントマター** | キーの欠落、`status` が `draft` / `review` / `approved` 以外、`updated_at` が ISO 8601 でない | テンプレートでコメントアウトされている任意キー |
| **プレースホルダー残存** | **2 系統**（`status-protocol.md` §7）の残存。`<UPPER_SNAKE>` 系統と、機械的に埋めるべき `{{UPPER_SNAKE}}` 系統の未置換をいずれも見る（本文・フロントマターを問わない） | **不要理由が併記されている箇所**（「不要と判断済み」として扱う。理由の妥当性は ③ が見る）／**小文字を含む山括弧**（`<feature>` のようなパス表記、`<br/>`、`<https://…>`）／**2 系統以外の表記**（単一の波括弧、角括弧、`TBD` のような語。プレースホルダーではないため ① では見ない） |
| **ID 書式** | `ID 書式` に反する ID、当該ファイル内での重複 | — |
| **欠番の再利用** | 廃止済み ID と同じ番号が別の項目に付与されている（要求IDのみ） | 欠番がそのまま空いている（正常） |
| **参照リンク切れ** | Markdown リンク・相対パス参照の参照先が存在しない、または存在しても空 | 外部 URL |
| `追加の存在検査` | 指定された項目が存在しない | — |

4. 指摘を `報告単位` で整理し、**層 ①** として `gate-report` に渡す。
5. **形式の不備を 1 件でも検出した場合、その事実を呼び出し元へ明示する。** ② 意味チェックへ進んではならない（形式が満たない文書の中身は評価しない）。

---

## 出力の形

指摘 1 件につき次の 3 つを揃える。これ以上の情報（重大度・合否・推奨修正）を付けない。

| 項目 | 内容 |
|---|---|
| 層 | ① |
| 対象箇所 | ファイル / セクション / 行 |
| 指摘内容 | 何が期待と異なるかの事実のみ |

---

## 禁止

- **対象成果物を修正しない。** 自動修正は行わない。
- **合否を出さない。重大度を付けない。**
- ② の判断（網羅性・妥当性・矛盾の意味）に踏み込まない。存在と形式のみを見る。
- 自由形式の文書（RFP）に本 Skill を適用しない。① はテンプレート化された成果物に対してのみ成立する。
- テンプレートに無いセクションを「あるべき」として指摘しない。
