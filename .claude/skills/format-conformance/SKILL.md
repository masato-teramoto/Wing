## 概要

対象成果物の構造（見出し・必須セクション・フロントマター）とID書式が、テンプレートおよび
`references/paths.md` §5 の命名規約に適合しているかを検証する。呼び出し元（合成 Skill）が
`対象パス` と `テンプレパス` を指定することで、Phase 1（要求ID書式）・Phase 2（プレースホルダー・
構造）・Phase 3（スキーマ・依存先実在）・Phase 4（要件ID書式・US/AC存在）・Phase 5（design書式・
必須セクション）・Phase 6（docs必須セクション）・Phase 7（要件ID紐づけ・完了条件存在）のいずれの
検証にも使い回せる、汎用の構造検証観点である。

## 入力

| 項目 | 内容 | 指定例 |
|---|---|---|
| 対象パス | 検証する成果物（明示されたパス一覧） | `.aidd/requirement-list.md` / `steering/*.md` |
| テンプレパス | 構造の正 | `Templates/Flow/requirement-list.md` |
| ID書式 | 当該成果物で使うIDの書式。IDを持たなければ「なし」 | `要求ID = REQ-\d{3,}` / `要件ID = 数値のみ` / `なし` |
| 追加検証 | 依存先実在・US/AC存在など、対象成果物固有の追加検証項目。無ければ「なし」 | `依存先 feature が feature-list.md に実在するか` |
| 報告単位 | 何を1件の指摘にするか | `要求ID` / `ファイル × セクション` |

**指定が無い項目を推測で補わない。** 上の項目が欠けていれば検査を始めず、入力不足として呼び出し元へ返す。

## 手順

1. `テンプレパス` を読み、必須セクション見出し（`#`〜`####`）・フロントマターのキー集合・プレースホルダーの位置を構造の正として控える。
2. `対象パス` の各ファイルについて、フロントマターのキー集合と見出し構造をテンプレートと突き合わせる。
   必須項目の欠落や許されていない追加を指摘する。テンプレートが任意とした節の省略や、人間の不要理由を伴うplaceholderを不備と断定しない。
3. 次を個別に検査する。

   | 検査 | 指摘にする | 指摘にしない |
   |---|---|---|
   | フロントマター | キーの欠落、`status` が `draft` / `review` / `approved` 以外、`updated_at` がオフセット付き ISO 8601 でない | テンプレートでコメントアウトされた任意キー |
   | プレースホルダー残存 | `references/status-protocol.md` §7 の2系統（人間が埋める `<UPPER_SNAKE>` と、機械的に埋める `{{UPPER_SNAKE}}` の未置換）の残存。本文・フロントマターを問わない | 不要理由が併記された箇所（理由の妥当性は③が見る）／小文字を含む山括弧（`<feature>`・`<br/>`・`<https://…>`）／2系統以外の表記（単一波括弧・角括弧・`TBD` 等の語） |
   | プレースホルダー削除 | テンプレートにあるプレースホルダーが、値にも不要理由付きの残置にもならず消えている（保持が規約） | テンプレートが任意とした節ごとの省略 |
   | ID書式 | `ID書式` に反するID、当該ファイル内でのIDの重複 | `ID書式` が「なし」 |
   | 参照リンク切れ | Markdown リンク・相対パス参照の参照先が存在しない、または存在しても空 | 外部 URL |

4. `references/paths.md` §5 の命名規約（ID書式・feature 名の完全一致など）に沿って、ID・ファイル名を検証する。
5. `追加検証` が指定されていれば、それに従って個別の書式・存在検証を行う（依存先実在・US/AC存在・
   完了条件記述の存在など）。
6. 指摘は `報告単位` でまとめる。
7. ① で形式の不備を検出した場合、呼び出し元の合成 Skill はこれ以降の観点（②）に進まない
   （`references/status-protocol.md` §6）。この判断は合成 Skill 側が行うため、本 Skill は
   検出した不備をすべて列挙して返すだけでよい。

## 出力の形

```
{ id, location, finding, is_rollback_candidate }
```

| フィールド | 内容 |
|---|---|
| `id` | この Skill 内で一意な通し番号 |
| `location` | ファイルパス・セクション見出し・行 |
| `finding` | 欠落/書式違反の事実（例: 「フロントマターに `status` が無い」「要求ID `REQ-12` が3桁未満」） |
| `is_rollback_candidate` | 通常 `false`（形式不備は同一フェーズ内で直せるため） |

## 禁止

- 対象成果物・テンプレートを書き換えない
- 合否を出さない（②以降に進めるかどうかは呼び出し元が判断する）
- 意味的な妥当性（内容の正しさ）を判断しない（それは他の観点 Skill の役割）
- 自由形式の文書（RFP）に適用しない。テンプレートに無いセクションを「あるべき」として指摘しない
