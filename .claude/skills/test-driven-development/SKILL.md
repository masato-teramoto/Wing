# test-driven-development — 挙動を一つずつ赤から緑へ実装する

## 対象と確認事項を揃える

- 対象タスク、追加・変更する挙動、受入基準、編集する実装とテストの位置を確認する。
  TDDを採用した挙動変更に本手順を使う。文書・設定だけの変更へ一律に適用しない。
- プロジェクトのテスト実行方法と既存テストを確認し、対象テストと回帰確認に使うコマンドを選ぶ。
  フレームワークや新しい依存は本パックを理由に追加しない。
- 次の一周で示す挙動を一つに絞る。テスト名が無関係な二つの期待を接続しているなら、
  一つの挙動を選び、残りは後の一周へ分ける。複数テストをまとめて先行作成しない。

## RED：実装前の失敗を観測する

1. 選んだ挙動を表す最小のテストを一つ書く。対応する実装コードはまだ書かない。
   新しい一挙動のテストを作るときは、次の順に組み立てる。

   - 前提となる状態と入力を準備する（Arrange）。
   - 対象の操作を実行する（Act）。
   - その操作から観測できる期待結果を確かめる（Assert）。

   テスト名には条件と期待する挙動を表し、何が満たされないと失敗するかを読めるようにする。
   名前と各確認が同じ一挙動を指しているか確かめ、複数の独立した期待があれば次の一周へ分ける。

2. テストを実際に実行し、コマンド、実出力、終了結果を残す。
3. 失敗理由を受入基準と照合し、次の表で進め方を確認する。

| 観測した結果 | 次に行うこと |
|---|---|
| 追加する挙動が未実装のため期待を満たさない | 期待と失敗理由の対応を記録し、GREENへ進む |
| 構文エラー・タイプミス・実行準備の不備でテスト自体が動かない | テストと実行準備を直して再実行する。挙動のREDとして数えない |
| 書いた直後から成功したが、要求された期待を捉えていない | 要求との対応を調べ、その未実装の挙動を観測するテストへ直して再実行する |
| 書いた直後から成功し、要求された挙動を既存実装が既に満たしている | 要求・入力・期待結果と実行結果の対応を記録し、追加実装不要として報告へ進む。新しいTDDサイクルのRED/GREENを実施したことにはしない |
| 実行できない | 実行できない理由と対象を記録する。失敗を観測したことにはしない |

初回成功だけで「要求は既に満たされている」と決めず、テストが必要な条件と期待を実際に確かめているかを読む。
要求が既に満たされている場合は、REDを作るために別の要求を発明したり、正常な既存実装を壊したりしない。

## GREEN：テストを変えずに最小実装する

- REDで確かめた期待を満たす最小の実装だけを書く。別機能、周辺のリファクタ、要求外の改善を加えない。
- 同じテストを実行する。まだ失敗するなら、期待を満たすよう実装を修正する。
  成功させるためにアサーションを弱めたり、テストを削除・変更したりしない。
- テストそのものの誤りが判明した場合は、そのままGREENを続けずREDへ戻り、
  テストの訂正理由を記録して正しい失敗を観測し直す。
- 対象テストだけでなく既存テストも実行し、新しい失敗がないことを確かめる。
  この実行結果をGREENの証拠として残す。

## REFACTOR：成功を保って構造を整える

- 対象と既存のテストが成功してから、今回の変更範囲で構造を整える。
- 変更は小さく区切り、そのたびにテストを実行して成功を保つ。新しい挙動は追加しない。
- テストが失敗したら、構造変更による差を調べて成功状態へ戻す。失敗したまま次の挙動を追加しない。
- 次の挙動が残っていれば、次の一テストのREDから新しい一周を始める。

## REDの記録が無い場合

- テストと実装があるだけでは、テストが先に失敗した事実は示せない。REDの実出力が欠落・空・
  受入基準と無関係なら、その不足を記録する。
- 回帰テストの検出力を事後確認する場合は、現在の変更を保持できる使い捨ての比較環境で行う。
  修正を含む状態で成功を確認し、**同じテストを残して対象の修正だけを適用しない状態**で期待した失敗を確認し、
  修正を復元して再び成功を確認する。各状態と実出力を残す。
- 作業中の未commit変更を自動で破棄・revertしない。修正だけを外した比較状態を確実に作れない場合は、
  証拠を再構成できない旨を報告する。現在の成功結果で欠落を埋めない。
- 事後の赤緑確認は「テストが修正を検出する」証拠として記す。
  「最初からテスト先行で実装した」という時系列の証明へ置き換えない。

## 実装結果を報告する

挙動ごとに次をまとめ、実出力そのものかその保存先を添える。

| 項目 | 記録する内容 |
|---|---|
| 対象 | タスク・受入基準と今回の一挙動 |
| 既に要求を満たしていた場合 | 対応する要求、確認した入力・期待・実結果、追加実装が不要な理由。未実施のRED/GREEN/REFACTORはその旨 |
| RED | 実行コマンド、実出力、未実装の期待に対応する失敗理由 |
| GREEN | 最小実装の内容、同じテストの実出力、既存テストの結果 |
| REFACTOR | 構造変更の内容と、その後のテスト結果。実施しなければその旨 |
| 証拠の限界 | 未実行・失敗・RED欠落、事後再構成した場合はその事実と比較状態 |

テスト設計の品質は利用可能なら `test-design`、完了主張と証拠の照合は `completion-verification` の担当範囲を参照する。
別パックの呼出しや実行環境の作成は自動では行われない。
