## 概要

`.aidd/requirement-list.md` のうち、RFP の記述を要約して転記した行（出典種別が「RFP」の行）が、
元の RFP の意味を変えずに要約できているかを検証する。要約は情報量を減らす操作であるため、
「削って良い情報」と「削ってはならない条件・制約」を取り違えると、意味変化が起きる。

## 入力

| 項目 | 内容 | 指定例 |
|---|---|---|
| 対象 | 要約結果 | `.aidd/requirement-list.md` のうち出典種別=RFP の行 |
| 根拠 | 要約元 | `.aidd/rfp/**` の該当箇所 |

## 手順

1. `対象` の各行について、出典として記載されている RFP の該当箇所を `根拠` から特定する。
2. 要約前後で、条件・数量・範囲・除外事項などの**制約に相当する情報**が保持されているかを
   突き合わせる。
3. 要約によって主語・対象範囲が変わっていないか（例: 「管理者のみ」が「ユーザー全般」に
   広がっていないか）を確認する。
4. 単なる文言の簡略化（意味を変えない言い換え）は指摘しない。**制約・条件・範囲の変化**のみを
   指摘対象とする。
5. RFP 改版時は、改版後の RFP に照らして各行の差分判定（維持 / 変更 / 新規 / 廃止）が妥当かも見る
   （文言が変わったのに維持、削除されたのに廃止扱いでない等）。ID の増減の機械検査はスクリプトが担う。

## 出力の形

```
{ id, location, finding, is_rollback_candidate }
```

| フィールド | 内容 |
|---|---|
| `id` | この Skill 内で一意な通し番号 |
| `location` | 意味変化が疑われる要求一覧の行と、対応する RFP の箇所 |
| `finding` | 意味変化の事実（例: 「`REQ-007` は RFP の『管理者ロールのみ』という制約が要約で欠落している」） |
| `is_rollback_candidate` | 通常 `false`（同一フェーズ内での要約修正で解消できるため） |

## 禁止

- 対象成果物を書き換えない（要約を自動で修正しない）
- 合否を出さない
- 単なる言い回しの違いを意味変化として指摘しない
