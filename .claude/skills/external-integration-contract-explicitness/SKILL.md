## 概要

`specs/<feature>/design.md` 内で外部システム・外部APIとの連携が記述されている箇所について、
実装可能な契約として明示的に書かれているか（インターフェース仕様・認証方式・エラー時の挙動・
タイムアウト/リトライ方針が記述されているか）を検証する。

## 入力

| 項目 | 内容 | 指定例 |
|---|---|---|
| 対象 | 検証する記述 | `specs/<feature>/design.md` の外部連携記述 |
| 必須項目 | 契約として明示すべき項目（既定） | インターフェース仕様・認証方式・エラー処理・タイムアウト/リトライ |

## 手順

1. `対象` から外部システム・外部API連携の記述箇所を抽出する。
2. 各箇所について `必須項目` それぞれが明示されているかを確認する。
3. 「〜と連携する」とだけ書かれ、契約の詳細（何を送り何を受け取るか、失敗時にどうするか）が
   書かれていない箇所を指摘する。

## 出力の形

```
{ id, location, finding, is_rollback_candidate }
```

| フィールド | 内容 |
|---|---|
| `id` | この Skill 内で一意な通し番号 |
| `location` | 契約が不明瞭な外部連携記述の箇所 |
| `finding` | 不明瞭さの事実（例: 「決済代行サービスとの連携について、タイムアウト時の挙動が記述されていない」） |
| `is_rollback_candidate` | 通常 `false`（同一フェーズ内での記述追記で解消できるため） |

## 禁止

- 対象成果物を書き換えない（契約内容を自動で補完しない）
- 合否を出さない
- 外部サービスの実際の仕様を調査・断定しない（記述の明示性のみを検証する）
