## 概要

観点 Skill が出した指摘を、gate-report へ渡す前に 1 件ずつ確かめる。基準は `.claude/skills/finding-rules/SKILL.md`（検査役が最初に読んだもの）。確かめ役は指摘を直す・外すだけで、新しい検査はしない。重大度・同一性キーは L3 が決める。

## 入力

蓄積した指摘一覧（gate / kind / location / subject / summary / evidence / suggestion / recommendation / is_rollback_candidate）、除外一覧、findings_path から取り込んだ機械指摘、検査対象と上流の明示的なパス一覧、`confirmed_answers`、`learned`。

## 手順

1. 機械指摘（findings_path の行）は確かめの対象外。外さない・書き換えない。種類は finding-rules §2 の機械の対応どおり、確かめ役の欄は `-` とする。
2. 各指摘の location を Read し、指摘した問題がその箇所に実在するかを確かめる。上流との食い違い・欠落を言う指摘は、上流の該当箇所も Read する。
3. 問題が実在しない、evidence の引用が対象に無い、指摘が対象を取り違えている場合は、指摘から外して除外へ移す。除外の出典は `verify:<理由>`。finding-rules §4 の出さない事項に当たると分かったものは、その出典（`rule:` / `answer:` / `learned:`）で除外へ移す。
4. 種類を finding-rules §2 の定義に照らす。誤っていれば直し、確かめ役の欄に `種類を変更：<元> → <新>：<理由>` と書く。変更が無ければ `確認済み`。迷ったら上の行を選ぶ。種類が業務の欠落・矛盾の指摘は、ほかの種類に変えない（根拠が無ければ手順3で外すだけ）。
5. 要約が 60 字を超えていれば、意味を変えずに 60 字以内へ書き直す（結論を先に、「何が・どこで」）。削った内容は evidence に残す。
6. 種類が業務の欠落・矛盾／業務のあいまい・不足で recommendation が無ければ、finding-rules §1 の形で付ける。軽微で修正案が無く、書けるものは修正案を足す。
7. finding-rules §5 に沿って重複をまとめる。同じ箇所・同じ原因の指摘は 1 件を残す。残すのは**重大度の高い種類の指摘**（業務の欠落・矛盾 → 業務のあいまい・不足 → 軽微の順）で、重大度が同じなら持ち主の表の観点、無ければ先に出した観点とする。業務の指摘を軽微の指摘に吸収させない。残す指摘の evidence にほかの観点も同じ箇所を指摘した旨を書く。外した側は除外へ移し、出典を `verify:重複（<残した観点>と同じ箇所・原因）` とする。同じ対象を指す指摘は対象の語を揃える。
8. 確かめた指摘一覧（確かめ役の欄を含む）と除外一覧を、順序を保って gate-report へ渡す。

## 禁止

- 判断・理由を書かない。合否・承認・重大度・差戻し先の確定をしない
- 機械指摘を外す・書き換える・種類を変える
- 指摘を黙って消す（外すときは必ず除外に出典と理由を残す）
- 業務の欠落・矛盾をほかの種類に下げる
- 新しい指摘を足す、確かめの名目で観点の検査をやり直す
- 検査対象・上流・ゲート記録・inspection_path に書き込む（書き出しは gate-report が行う）
