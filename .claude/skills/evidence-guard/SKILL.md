## 概要

対象成果物の記述のうち、指定された根拠元（上流成果物）に出典を持たない記述を検出する。
「推測で埋めた」「壁打ちで確定していないのに書かれた」記述を機械的な突合では拾えないため、
意味的に対象記述と根拠元を照合する。呼び出し元が「対象」と「根拠」を指定することで、Phase 1〜7
すべての「根拠なき記述検出」に使い回せる（数値の根拠・設計判断の根拠を個別に見る場合もある）。

## 入力

| 項目 | 内容 | 指定例 |
|---|---|---|
| 対象 | 検査する成果物・記述範囲 | `.aidd/requirement-list.md` 全行 / `tasks.md` の数値記述のみ |
| 根拠 | 出典として認める上流成果物 | `.aidd/rfp/**` / `specs/<feature>/design.md` のみ |
| 根拠の粒度 | どこまで示せれば根拠ありとみなすか（任意。未指定なら `根拠` 内の該当箇所をファイル・節で特定できること） | `要求IDの特定` / `RFP 内の実在位置` / `steering のセクション名` |
| 除外 | 根拠を要求しない既知のプレースホルダー等（任意） | `TBD` / `未定` |
| 重点 | 呼び出し元が特に見させたい記述の種類（任意） | `design.md に無い API 形状・エンティティ・技術選定` |

## 手順

1. `根拠` を読み、裏付けとして使える事実の集合を把握する。
2. `対象` から、事実・数値・設計判断として断定的に記述されている箇所を抽出する。特に次と `重点` を見る。

   | 見る対象 | 理由 |
   |---|---|
   | 具体的な数値（性能目標・保持期間・上限値・件数・桁数） | 推測補完が起きやすく、もっともらしく見える |
   | 固有名（製品名・サービス名・部署名・システム名・バージョン） | 上流に無い固有名はほぼ補完である |
   | 業務上の判断（承認者・権限・例外処理・優先順位） | 業務知識で埋められてしまう |
   | 「〜とする」「〜である」で締める前提の宣言 | 決定として下流に伝播する |
   | 記入欄に新たに書き込まれた `TBD` / `未定` | 未確定を値として書いた状態であり、確定済みと誤読される |

3. `除外` に該当するプレースホルダー由来の記述は対象から外す
   （`references/status-protocol.md` §7。`TBD`/`未定`/`_(未記入)_` はプレースホルダーではなく
   テンプレート由来の注記として元から存在する場合だけ除外する。新たな回答として追加されたTBD等は除外しない）。
4. 各記述について、`根拠` の中に `根拠の粒度` で示せる裏付けがあるかを確認する。`根拠` が複数指定
   されている場合、いずれにも裏付けが無いことを確認してから指摘する。
5. 裏付けが無いものを、次を書き分けて指摘する。

   | 区分 | 意味 |
   |---|---|
   | 根拠なし | `根拠` のどこにも対応する記述が無い |
   | 根拠の飛躍 | 対応する記述はあるが、そこから当該の値・断定は導けない |
   | 出典不明 | 根拠がある可能性はあるが、成果物側に出典が書かれておらず追跡できない |

### 指摘にしないもの

- 人間の不要理由が明記されたプレースホルダー、および未記入のまま残されたプレースホルダー
  （推測補完の反対であり、残存は format-conformance が拾う）
- 上位方針への準拠を宣言した引用（「`security.md` 準拠」等）。参照先に該当記述があれば根拠ありとみなす
- テンプレートに元から含まれる例示・注記・初期値（`Templates/` と突き合わせて同一のもの）

## 出力の形

```
{ id, location, finding, is_rollback_candidate }
```

| フィールド | 内容 |
|---|---|
| `id` | この Skill 内で一意な通し番号 |
| `location` | 根拠のない記述の箇所 |
| `finding` | 根拠なし／根拠の飛躍／出典不明の別と事実（例: 「根拠なし: 非機能要求の SLO 値 `99.9%` に対応する記述が `.aidd/requirement-list.md` に無い」） |
| `is_rollback_candidate` | 壁打ちで判明した新規要求など、フロー外の確認が必要な場合は `true` |

## 禁止

- 対象成果物を書き換えない（根拠が無い記述を削除・修正しない）。正しい値を推測して提案することもしない（それ自体が推測補完である）
- 合否を出さない
- 記述の内容の正しさを評価しない。見るのは根拠に辿れるかの一点である
- 上流に記述が無いことを「上流の欠落」と断定しない。指摘は「この記述の根拠が示せない」までとし、
  上流を直すか当該記述を消すかは ③ が決める
- プレースホルダー（§7 の2系統）を、不要理由付き・未記入のどちらの場合も根拠なき記述として指摘しない
