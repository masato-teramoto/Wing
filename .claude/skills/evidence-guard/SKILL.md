# evidence-guard（② 推測補完の検出）

> 出典: フロー設計 `00` §8.1。層 **②**。呼び出し元は各フェーズの `<Phase>-Check-Subagent`。

本フローは **根拠のある値のみを書く**ことを前提に成立している。上流に辿れない記述は、下流のどのゲートでも「もっともらしい」ために検出されにくい。本 Skill はその一点だけを見る。

---

## 入力（呼び出し時に必ず指定する項目）

| 項目 | 内容 |
|---|---|
| `対象成果物` | 検査するファイル（複数可） |
| `根拠として認める成果物` | 記述の裏付けとして認めるファイル群。ここに含まれないものを根拠として認めない |
| `根拠の粒度` | どこまで示せれば根拠ありとみなすか（例: 要求ID の明示 / 章・見出しの特定 / steering のセクション名） |
| `報告単位` | 何を 1 件として報告するか |

### 呼び出し例

| フェーズ | `根拠として認める成果物` | `根拠の粒度` |
|---|---|---|
| Phase 1 | RFP、人間が壁打ちで確定した回答 | `RFP` 種別は RFP 内の実在位置、`壁打ち` 種別は人間の確定回答 |
| Phase 2 | `.aidd/requirement-list.md`（特に `非機能` / `制約`）、人間の確定回答 | 要求ID の特定、または人間の回答の引用 |
| Phase 5 | 当該 feature の `requirements.md`、`steering/` 一式、DS の `pattern.json` / `component-spec.json` / `brand-principles.md` | 要件ID の特定、`steering/` のファイル名とセクション名、または DS のパターン名・部品名 |

**Phase 5 では、生成規約が明示的に許している次を指摘しない**（`wireframe-authoring` SKILL.md「画面に載せる情報の根拠」）。DS のパターンが構えとして定める構造要素 / requirements の `Adjacent` に列挙された隣接 feature のデータの読み取り専用の参照表示 / 固定値ダミーデータそのもの / requirements に文言が無い状態（空・エラー等）の文言。**指摘するのは、requirements にも steering にも根拠が無い「項目・制約・採番規則」を画面上で確定させている箇所である。**

---

## 手順

1. `根拠として認める成果物` を読み、**裏付けとして使える事実の集合**を把握する。
2. `対象成果物` を読み、**断定的に書かれている記述**を列挙する。特に次を重点的に見る。

| 見る対象 | 理由 |
|---|---|
| 具体的な数値（性能目標・保持期間・上限値・件数・桁数） | 最も推測補完が起きやすく、かつ最もらしく見える |
| 固有名（製品名・サービス名・部署名・システム名・バージョン） | 上流に無い固有名は、ほぼ確実に補完である |
| 業務上の判断（承認者・権限・例外処理・優先順位） | 業務知識で埋められてしまう |
| 「〜とする」「〜である」で締める前提の宣言 | 決定として下流に伝播する |
| `TBD` / `未定` のような**未確定を表す語が記入欄に書き込まれている** | プレースホルダーを消して未確定を値として書いた状態であり、確定済みと誤読される。未確定なら**プレースホルダーを残す**のが正しい振る舞いである |

3. 各記述について、`根拠として認める成果物` の中に `根拠の粒度` で示せる裏付けがあるかを確認する。
4. 裏付けが無いものを報告する。報告時は次を書き分ける。

| 区分 | 意味 |
|---|---|
| **根拠なし** | `根拠として認める成果物` のどこにも対応する記述が無い |
| **根拠の飛躍** | 対応する記述はあるが、そこから当該の値・断定は導けない |
| **出典不明** | 根拠がある可能性はあるが、成果物側に出典が書かれておらず追跡できない |

5. 指摘を `報告単位` で整理し、層 **②** として `gate-report` に渡す。

---

## 指摘にしないもの

- **不要理由が明記されたプレースホルダー。** 人間が「必要ない」と判断して理由を書いた箇所は、推測補完ではない。
- **未記入のまま残されたプレースホルダー。** これは推測補完の反対であり、正しい振る舞いである（残作業として `format-conformance` が別途拾う）。
- **上位方針への準拠を宣言した引用**（「`security.md` 準拠」など）。参照先に記述があれば根拠ありとみなす。
- **テンプレートに元から含まれる例示**。テンプレート由来の記述かどうかを `Templates/` と突き合わせて確認する。テンプレートが注記・初期値として持つ `TBD` / `_(未記入)_` も、突き合わせて同一なら記入結果ではないため指摘しない。

---

## 禁止

- 対象成果物を修正しない。**正しい値を推測して提案することもしない**（それ自体が推測補完である）。
- 合否を出さない。重大度を付けない。
- 記述の**内容の正しさ**を評価しない。見るのは **根拠に辿れるか**の一点である。
- 上流に記述が無いことを「上流の欠落」と断定しない。指摘は「この記述の根拠が示せない」までとし、上流を直すか当該記述を消すかは ③ が決める。
