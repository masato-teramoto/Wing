# traceability（① / ② トレーサビリティ突合）

> 層 **① / ②**。呼び出し元は各フェーズの `<Phase>-Check-Subagent`。

手順は 1 つに保ち、**フェーズごとに変わる対象だけを呼び出し時に指定する**。フェーズ別に別 Skill を作らない。

---

## 入力（呼び出し時に必ず指定する項目）

| 項目 | 内容 |
|---|---|
| `上流の成果物` | 突合の分母になるファイル（複数可） |
| `下流の成果物` | 突合の分子になるファイル（複数可） |
| `ID / 項目の書式` | 突合キーの書式。ID を持たない要素の場合は「何を同一とみなすか」の定義 |
| `突合方向` | `上流 → 下流`（網羅確認） / `下流 → 上流`（逆引き確認） / `双方向` |
| `報告単位` | 何を 1 件として報告するか |
| `分母の絞り込み` | 分母から除外する行の条件。無ければ「なし」 |

`分母の絞り込み` は誤検出を防ぐために必須の指定である。指定を省くと、対応関係を持ちえない行が常に不整合として報告される。

### 呼び出し例

| 指定項目 | Phase 3 での値 | Phase 6 での値 |
|---|---|---|
| 上流の成果物 | `.aidd/requirement-list.md` | `specs/*/design.md` |
| 下流の成果物 | `.aidd/feature-list.md` | `docs/` 一式 |
| ID / 項目の書式 | 要求ID（`REQ-` 接頭辞付き） | エンティティ名・業務コード値 |
| 突合方向 | 上流 → 下流（網羅確認） | 下流 → 上流（逆引き確認） |
| 報告単位 | 未割当の要求ID | docs 未反映の design 要素 |
| 分母の絞り込み | 分類が `機能` の行のみ | なし |

---

## 手順

1. `上流の成果物` を読み、`ID / 項目の書式` に従って **突合キーの集合**を抽出する。
2. `分母の絞り込み` を適用して分母を確定する。
3. `下流の成果物` を読み、同じ書式で突合キーの集合を抽出する。
4. `突合方向` に従って差分を取る。

| 突合方向 | 報告するもの |
|---|---|
| 上流 → 下流 | 下流のどこにも現れない上流のキー（**取りこぼし**） |
| 下流 → 上流 | 上流に存在しない下流のキー（**参照先不在**）。下流が上流に無いものを参照している |
| 双方向 | 上記の両方 |

5. **キーの一致だけで足りない場合は、意味の落とし込みも見る（層 ②）。** ID が書かれていても、上流の内容が下流で満たされていないなら報告する。この判定を行ったかどうかを指摘に明示する。
6. 指摘を `報告単位` で整理し、層（① / ②）とともに `gate-report` に渡す。

### 上流が自由形式の場合（RFP）

上流が ID を持たない自由形式の文書のときは、`ID / 項目の書式` に **何を同一とみなすか**が指定される（RFP なら「要求の意味単位」）。この突合は **層 ②** である。

- **章・見出しのような構造単位を突合キーにしない。** 見出しの有無・粒度は案件ごとに異なり、単位の切り出し自体が推論になるため ① にならない。
- 報告は **上流の該当箇所を引用**して示す（下流に見当たらない記述を、位置ではなく内容で特定できるようにする）。

---

## 独立導出が要求される場合

**網羅性の欠落が下流のどのゲートでも検出できない検査**では、より強い形をとる。呼び出し元が「独立導出」を指定した場合は次に従う。

1. **`下流の成果物` を先に読まない。**
2. `上流の成果物` だけから、期待される要素を独立に導出する。
3. 導出を書き留めたうえで、はじめて `下流の成果物` を読み、突き合わせる。

現在の適用先は **Phase 1**（RFP からの独立抽出。層 ②）と **Phase 6**（各 design からの独立抽出）である。

**作成側が抽出した結果を再利用しない。** 突合を伴う検査では、ゲート側が上流成果物を読み直して導出する。

---

## 禁止

- 対象成果物を修正しない。
- 合否を出さない。重大度を付けない。
- `分母の絞り込み` の指定が無いまま分母を自分で決めない（呼び出し元へ確認を返す）。
- **自由形式の上流（RFP など）を章・見出し単位に区切って網羅表を作らない。** 単位の切り出しが推論になるため ① として成立せず、抽出しなかった箇所を並べるだけで検出力を持たない。
- 対応関係を持ちえない行を分母に含めない（例: 出典種別が `壁打ち` の要求を RFP 突合の分母に入れる、`非機能` / `制約` の要求を feature 割当の分母に入れる）。
