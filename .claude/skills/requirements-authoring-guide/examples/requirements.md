# 記入例: 読書リストの本を既読にする

**説明専用・合成資料。** 以下の依頼者、条件、数値は、この例の入力として作った架空の設定である。
実案件で確認・合意された値ではなく、他案件の既定値にもならない。実装・測定は行っていない。

## この例の依頼条件

ローカルの読書リストで、選んだ本を既読にできるようにする。書名は公開されたサンプル名のみを用い、
利用者登録、クラウド同期、永続化は扱わない。各本は一意なID、書名、既読状態を持つ。
対象は、デスクトップブラウザの単一画面に表示された100冊のサンプルリスト。

以下の性能値は架空の依頼者がこの練習用に決めた値として扱う。作成者が不明点を補った実績ではない。
要件IDの母集合は **FR-01、FR-02、FR-03、NFR-01、NFR-02の5件**。受入条件は各IDの行に内包する。

## 機能要求と受入条件

| ID | 要求強度・要求 | 条件／操作 → 期待される応答 |
|---|---|---|
| FR-01 | 画面は選択した未読の本を既読へ変更しなければならない（MUST） | ID=b1が未読、b2が未読のとき、b1の「既読にする」を選ぶ → b1の表示は既読になり、b2の状態と全書名は変わらない |
| FR-02 | 既読の本への同じ操作で状態を変化させてはならない（MUST NOT） | b1が既読のとき、b1への既読操作を繰り返す → b1は既読のままで、件数・書名・他の本の状態は変わらない |
| FR-03 | 対象IDが存在しない操作は理由を示し、リストを変更してはならない（MUST NOT） | 存在しないIDへの既読操作を受けたとき → 「対象の本が見つかりません」を表示し、リストは操作前と同じ状態を保つ |

## 非機能要求

| カテゴリ | 採否と理由・確認条件 |
|---|---|
| Performance | 対象。NFR-01を適用する |
| Security & Privacy | 対象。NFR-02を適用する。実ユーザー情報を含む運用や認証は対象外 |
| Reliability & Availability | 対象。同一操作の反復と存在しないIDで状態が壊れない期待をFR-02・FR-03に具体化する。プロセス終了後の保持・長期稼働率は、単一セッションの練習機能なので対象外 |
| Compliance | 対象外。この例は公開サンプルによるローカル教材で、法定保存や業界認証への適合を主張しない。実サービス化する際の採否判断は引き継がない |

| ID | 要求強度・要求 | 測定・観測条件 |
|---|---|---|
| NFR-01 | 既読操作の表示応答時間は各測定回のp95が150ms以下でなければならない（MUST） | 練習用デスクトップ・ローカル配信・同一ブラウザ設定・100冊の初期データで、操作開始から対象行の既読表示までを測る。各回40操作、初期状態へ戻して5回測定する。各回の40値を昇順にし、38番目の値をp95とする。全測定回の条件・個別値・p95を残す。負荷・端末条件を変えた値と混ぜない |
| NFR-02 | 既読操作に伴って書名・既読状態を外部送信してはならない（MUST NOT） | サンプル画面の初期表示後、FR-01・FR-02・FR-03の操作中に出る通信を観測し、書名・既読状態を含む外部送信がないことを確認する。初期表示用の静的ファイル取得と操作情報の送信を区別する |

文書の自己確認では、NFRの採否宣言と、対象カテゴリの期待・確認方法が記載されているかを点検する。
これはNFRの達成や性能測定済みを意味しない。

## In scope

- 現在表示中の本を既読にする操作、既読表示、同じ操作の反復、存在しないIDへの応答。
- 上記5件の要求に対する計画と検証仕様の作成。

## Out of scope

- 未読へ戻す操作、本の追加・削除・並べ替え: 今回の一機能から分け、必要時に別要求として検討する。
- ブラウザ再読込後の保存、クラウド同期、利用者アカウント: 永続化や他利用者との共有を扱わない教材のため除外。
- 外部書誌サービスとの連携: 初期データは教材側が供給するため除外。書誌の正確性をこの機能が保証しない。

## 隣接への期待と非所有

教材側は一意IDを持つ初期リストと画面表示の場を供給する。この機能は書誌取得やID発行を所有しない。
入力IDが一覧にない場合の振る舞いはFR-03で扱う。実案件で初期データや環境が未確定なら、この設定をコピーせず
未確定事項として回収する。
