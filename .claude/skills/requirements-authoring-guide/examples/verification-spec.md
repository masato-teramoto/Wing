# 記入例: 検証仕様

**説明専用・すべて未実施。** この一覧は検証の予定を表し、成功ログやテスト結果ではない。
[要件例](requirements.md)と[実装計画](implementation-plan.md)を対象にする。
検証仕様IDの母集合は **CHECK-01、CHECK-02、CHECK-03、CHECK-04、CHECK-05の5件**。
この件数は題材の構成であり、他案件へ固定数を要求しない。

| ID | 明示要求参照 | 前提と操作 | 観測する期待結果・残す予定の証拠 |
|---|---|---|---|
| CHECK-01 | FR-01 | b1・b2を未読で表示し、b1の既読操作を行う | b1だけが既読になり、b2と全書名は不変。操作前後の一覧と対象行を記録する |
| CHECK-02 | FR-02 | b1を既読で表示し、b1への既読操作を繰り返す | 件数・書名・全既読状態が操作前後で一致する。入力と結果の値を記録する |
| CHECK-03 | FR-03 | 既知の一覧にないmissing-bookへ操作する | 「対象の本が見つかりません」が表示され、一覧の全値が変わらない。表示理由と操作前後の一覧を記録する |
| CHECK-04 | NFR-02 | 初期画面の読み込み後、CHECK-01〜03の操作中の通信を記録する | 書名・既読状態を含む外部送信がない。観測期間と通信一覧を残し、初期静的ファイル取得と区別する |
| CHECK-05 | NFR-01 | 練習用デスクトップ・ローカル配信・同一ブラウザ設定・100冊で、各回40操作を5回、回ごとに初期化して測る | 操作開始→対象行の既読表示の40値と昇順38番目を各回残す。各回p95≤150msを確認し、環境条件と個別値を併記する |

CHECK-01〜04の結果やCHECK-05の実測値はここにはない。文書間で要求を扱う計画がそろっていることと、
その挙動が実装され期待を満たしたことを分ける。結果の記録時には未実施・未達・測定不能を成功へ読み替えない。
