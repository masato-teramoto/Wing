- 条件付き収載は利用者指示 2026-09-01 と選定案 rev78 による advisory。監査は read-only のまま維持する。

- **S3a／S3b の分割**は選定案 §1 の設計（作成＝S3a／read-only 監査＝S3b）に従う。
- **機械検査と読みの区別**は K-03（「機械的検査の対象として明示する。ただし判定の主軸ではない」）を監査
  手順へ展開した適用注記であり、新規 invariant ではない。**機械で確定できる範囲は case・単複・用語集に
  明示された alias まで**とし、送り仮名・区切り記号は候補抽出、言い換えと未定義語は人の判定に分けた
  （正本の境界を超えて機械判定を広げない）。
- **fail-closed の条件**: 用語集の不在に加え、重複・空定義・構造不成立・矛盾で**正準用語を一意に確定
  できない場合**も推定せず S3a へ redirect して停止する（誤った単一置換案の防止）。
- **入力契約（カード由来ではない）**: `canonical_glossary_ref`／`audit_targets` の必須化、**解決規則6項**、
  および**終端の順序つき判定7段**は
  **KA-REF-024 に由来しない**。同カードは用語集の**内容規約**（K-01〜K-04）であって、正準用語集の**所在の
  特定**には触れていない。したがって本節は advisory なカード知識ではなく、**利用者指示に基づく運用契約**
  として区別して記録する（由来: ユーザー指示 2026-08-28・第37回レビュー。選定案 §2 の S3a/S3b 追補に収載）。
  バッジの全称形「本パックの**カード由来の知識**は全項が advisory」はこの追加後も成立する。
- **non-final の遮断**: 読取不能等で止まった場合の途中結果は `acceptance-review` へ handoff しない
  （final のみ handoff 可）。non-final の宣言だけでは下流での誤用を防げず、被覆未確定の結果が受入判定に
  かかる経路が残るため、引き継ぎ側で閉じた。
- **参照先0件は順2 と順7 に尽きる（網羅・排他）**: **不存在を確認済み**＝順2 で redirect、**それ以外の0件は
  すべて順7** で確認して停止。順7 には「読める候補はあるが上位参照も自己宣言も無く**正準性を確認できない**」
  「**有効性を判定できない**」「**監査スコープへの適用性を判定できない**」を含む。候補が読めること自体は
  正準性の根拠にならないため、候補の存在を理由に順2（不存在を確認済み）へ流さない。
- **未指定は停止事由ではない**: 終端順1 が見るのは **`audit_targets` の欠落・不良**と、**明示された**
  `canonical_glossary_ref` の**解決・読取不良**だけ。`canonical_glossary_ref` が**未指定なら探索へ進む**
  （順1 で止めると規則2 の探索経路へ到達できず、契約が自己矛盾する）。明示値が正常なら
  `{明示参照}` を解決済み集合として**探索を省略**する。
- **読取確認は探索由来にも及ぶ**: 上位文書・自己宣言から見つけた参照先も、**重複排除と件数判定の前に**
  全件を解決・読取確認し、**1件でも失敗したら省略せず確認して停止**する（redirect しない）。
  fail-closed 検査を明示値だけに掛けると、探索由来の壊れた参照が黙って件数から落ちる。
- **`audit_targets` の実効0件**: 列挙できても対象が0件（空ディレクトリ等）なら、空虚な「全件監査」を
  出さず確認して停止する（被覆の主張が空になるため）。
- **順5 の確認結果の扱い**: 否定・曖昧な回答なら停止。**別の参照が提示された場合は順1 の解決・読取検査へ
  戻す**（提示されたから正しい、としない）。
- **停止時は常に non-final**: いずれの停止でも final な監査結果を出さず、途中結果は non-final 明記・
  被覆を主張しない。監査の途中で対象や用語集が読めなくなった場合も同じ扱い。
- **終端は順序つき手順で排他化する（最終形＝7段）**: 条件を並列に並べる形では、「用語集が無い」が同時に
  「有効な正準指定0件」でもあるため重複が残る。**先に該当した終端で止まる**評価順を定めた——
  **順1** `audit_targets` の欠落・不良（実効0件を含む）／**明示された** `canonical_glossary_ref` の解決・読取
  不良＝確認して停止（**未指定は順1 の停止事由ではない**）／**順2** 不存在を**確認済み**＝redirect／
  **順3** 参照先（明示値・探索由来を問わず）の解決・読取に1件でも失敗＝確認して停止／**順4**（操作）参照先を
  正規化して重複排除／**順5** 参照先1件＝確認のうえ内容整合を見て監査を実行／**順6** 異なる参照先が2件以上＝
  redirect／**順7** 参照先0件（**順2 に該当しないすべての0件**）＝確認して停止。
  **「不存在を確認済み」（順2）と、それ以外の0件（順7）は別状態**であり、順序で一意に分かれる。
- **件数の数え方**: 数えるのは**指定の本数ではなく、指定が指す用語集の参照先を正規化して重複排除した集合の
  件数**（同じ用語集を索引と自己宣言の2経路が指しても1件）。**候補ファイルの件数は終端判定に使わない**——
  モノレポで別スコープの用語集を数に入れると誤検知するため、スコープ条件を「有効な正準指定」の定義に含めた。
- **redirect と確認停止の分離**: redirect（不存在を確認済み・参照先2件以上・単一用語集の内容不整合）は
  **用語集側の問題**、確認して停止（入力不足・解決不能・読取不能・**参照先0件〔順2 に該当しないすべて〕**）は**判断材料の
  不足**。「監査を始めない条件」節は**参照先が1件に確定した後の内容整合**のみを扱い、不存在と2件以上は
  順序側で先に判定するため重ねて列挙しない。
- **「有効な正準指定が複数」を停止条件に置く根拠**: 複数の語彙表の併存は K-02（語彙は成果物・工程を横断して
  同一）の破れであり、正準の確定は用語集の所有者＝S3a の領分。**K-02 は S3a が所有**するため本パックでは
  規範として重複収載せず、停止条件の**判断基準として参照するにとどめる**。
- **入力不足と用語集不備の分離**: 入力が渡っていない・明示値が不存在・読取不能・列挙不能な状態（終端順1）、
  および参照先の解決・読取に失敗した状態（終端順3）は確認で停止し、S3a へ redirect しない。redirect は用語集そのものが
  不在・不整合な場合に限る（過剰 redirect の防止）。**読めない対象の黙った除外**と、**参照障害を「用語集が
  無い」と誤認した redirect** の2つを同時に塞ぐ。読取不能は監査開始前に限らず**監査中も同じ扱い**とし、
  この状態では final な監査結果を出さない（non-final 明示・被覆の非主張）——S2 の「未解決のまま finalize
  しない」規律と同じ形。
- **再 compose 入力**: 本パックの再生成入力は **`assets/`（KA-REF-024）＋ 選定案 §2 の S3a/S3b 追補**である。
  カード由来でない運用契約は assets/ 側に存在しないため、`assets/` だけを入力にすると失われる。
  **対になる S3a も同じ条件**であり、KA-REF-024 を再 compose する際は両パックへ同時に適用する。
  本回は両パックを同時に再 compose し、rev78 の SO 選定も入力へ追加した。
- **参照の閉包**: 受入判定は `acceptance-review` への handoff（選定案 §5 の dependent／guard 関係に一致・
  任意ではない）。
- `activate_specializations` による SO の選択的活性化は **P3 では未導入**。SO-03 の対検査は上表の
  人間承認に基づく条件付き advisory であり、runtime selector・Contract の合否条件を追加しない。

  自律可能性のみを意味する）。したがって実務妥当性の留保は DRAFT 固有の警告ではなく、SKILL.md では
