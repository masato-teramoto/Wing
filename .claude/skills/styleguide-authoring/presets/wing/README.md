# プリセット `wing`

**出どころ**: 既存システム **WiNG（建設業務支援システム）** の画面ソース抜粋から、ルート A（既存 UI からの抽出）で起こした
STYLEGUIDE 一式。**抽出日 2026-09-09**。検証案件の mockup を作る過程で **0.3.0 → 0.3.7** の改訂を経て確定し、
**2026-09-15 に frontmatter の反映漏れを 2 度に分けて是正して 0.3.9**、さらに**同日、`sources.captures` の
絶対パスをファイル名だけに直して 0.3.10** にした（下の「是正」「抽出元のキャプチャ（同梱しない）」）。
**WiNG 系の実案件で、SG のルート C「プリセットの取り込み」が複製して使う初期値**である。

**中身（3 点・いずれも版 0.3.10）**

| ファイル | 中身 |
|---|---|
| `STYLEGUIDE.md` | 見た目の正。frontmatter の `tokens`（抽出値）+ §1〜§9 の本文 |
| `styleguide.css` | 機械可読形（同版）。**宣言は元版と 1 文字も変えていない** |
| `STYLEGUIDE-backlog.md` | WiNG 由来の**未処理 14 件**（現状で可 10 / 未判断 2 / 保留 2）。番号は `SGB-1` から振り直し、各行に旧番号を持つ。**+ 反映済 1 件（SGB-15）** |

**画像は同梱しない。** 抽出元のキャプチャ 5 点は**プリセットに含めない**（→「抽出元のキャプチャ（同梱しない）」）。
`STYLEGUIDE.md` の `sources.captures` は**ファイル名だけ**を持つ。

**落としたもの**: 検証案件に固有の**画面名・feature 名・項目名**、**その画面で測った px の実測値**、**工程の経緯**
（改訂の起点・台帳番号・目視の回数・人の発言の時刻・進捗ログ）。§1-2 改訂履歴は **1 行**に畳んである。
**この方針は 0.3.10 でも変えていない**（実測値は落としたまま。**画像も 1 枚も入っていない**）。
**残したもの**: frontmatter の **`tokens` 全値**（抽出値。1 値も変えていない）/ `sources.captures`（**0.3.10 から
ファイル名だけ。実体は同梱しない**）/ `sources.code`（WiNG 側の
抽出台帳）/ §2〜§8 の**クラス設計・部品の様式・段の値・器の作り方**（`.list-scroll` + 吸う列 / `<colgroup>` /
`table-layout: fixed` / `.control-group` / §4-10 シェル / §4-13 システムエラー画面 …）/ §9 のエージェント向け指示 /
**`styleguide.css` の宣言すべて**。**実測値は、画面名を持たない「測り方」として残してある。**

**使い方（SG のルート C）**

1. 3 点を**案件ルート直下に複製する**（台帳は未処理分だけなので、そのまま初期行にする）
2. frontmatter の `product` を案件名に、`route` を `preset` に直し、**`preset_origin.copied_at` に複製日を書く**（`preset_origin.name` / `version` / `extracted_at` / `sources` は据え置き）。
   **据え置いた `sources.captures` はファイル名だけで、実体は案件にも配布物にも無い**
   （**案件ルート配下を探さないこと**。実体の所在は `preset_origin.name` から
   `<配布ワークスペース>/.claude/skills/styleguide-authoring/presets/<name>/README.md` を見る）。
   **本文 H1 と `styleguide.css` 冒頭コメントの `{{製品・案件名}}` も直す**（frontmatter だけ直すと 2 箇所が記入欄のまま残る）。
   最後に **3 点を `{{` で全文検索**し、記入欄の残りが 0 であることを確かめる
3. §1-2 改訂履歴に初回の 1 行を積む — `| <version> | <日付> | 初回（プリセット wing 0.3.10 から複製） | 全節 | 未 |`
4. **`styleguide.css` は複製したものを使い、再生成しない**
5. **【人】が案件の既存画面と突合して確定する** — 本書は WiNG の再現であって、この案件の既存 UI から起こしたものではない。§1-1 / §1-1b の判断は **WiNG 側の決着**なので、そのまま引き継いでよいかを人が確かめる。
   **案件の既存画面が無いときの突合先が抽出元のキャプチャ**で、**同梱していないので取り寄せる**
   （→「抽出元のキャプチャ（同梱しない）」。**ここが配布物だけでは閉じない唯一の箇所**である）

**版の扱い**: **プリセットの版（0.3.10）を継続する**（`0.1.0` に戻さない）。複製先で 0.3.11 → 0.4.0 と上げてよい。プリセット側を直したときはプリセットの版を上げ、`preset_origin.version` との対応を保つ。

**是正（0.3.8・2026-09-15）**: 元版 0.3.7 は frontmatter と本文・CSS で数値が **2 件**食い違っていた
（`layout.content_max_width` = frontmatter 1280px / 本文・CSS 1480px、`layout.column.ordinal` = frontmatter 32px / 本文・CSS 42px）。
検証の 43 ページの実測は CSS の値で通っているため、**【人】判断で frontmatter を CSS 側（1480px / 42px）に揃えた**。
**`styleguide.css` の宣言は 0.3.7 と同一**（変えたのは冒頭コメントの版だけ）。§1-2 に 0.3.8 の行がある。

**是正（0.3.9・2026-09-15）**: **同じ「frontmatter への反映漏れ」類型の 3 件目**。
`layout.column` の 5 つ目の段 **`xwide`（620px）が frontmatter にだけ無かった**
（§4-4 の見出しの `class:` 列挙・本文の段の説明・`styleguide.css` の `--layout-column-xwide` / `.list-col-xwide` には在る）。
あわせて **§4-4 B 本文の `<colgroup>` クラス列挙にも `.list-col-xwide` が落ちていた**ので足した。
**`styleguide.css` の宣言は 0.3.7 と同一**（変えたのは冒頭コメントの版だけ）。§1-2 に 0.3.9 の行がある。

> **3 件とも「本文・CSS に在って frontmatter に無い / 食い違う」**という同じ形で出ている。
> **次に抽出・改訂をするときは、差分を追う前に frontmatter `tokens` の網羅を先に数えること**
> （自己確認 #1 は「frontmatter に在る値」と本文を突き合わせるので、**frontmatter に無い段は素通りする**）。
