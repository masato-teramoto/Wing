# completion-verification — 完了主張と証拠の照合

## 対象を確定する

報告テキスト、報告が対象とする変更・要件、添付された検証出力を読む。
完了、修正済み、テスト・ビルド合格、要件充足、GOなどの主張を一件ずつ取り出す。
その報告がタスク完了、commit、PR、次タスク、委譲の受入、GO判断などの根拠になるときに照合する。

早期計画、未完了と明示した推測的な進捗報告、完了系主張のないメモは適用外とする。
テストの設計品質・カバレッジ設計の妥当性や、コードそのものの品質はここで採点しない。

## 証拠を確かめてから主張する

1. **何を主張するかを特定する。** 対象の変更・要件・機能範囲を示す。「全部完了」を個別の主張へ分ける。
2. **何がその主張を証明するかを決める。** 下の対応表に沿って、実行コマンドや要件単位チェックを選ぶ。
3. **現在の状態に対して完全な確認を新規に実行する。** 同一の報告・反復内の出力を残す。
   コード変更後に再実行していない過去ログは、変更後の状態を証明しない。
4. **出力を全文読み、結果と対象範囲を確認する。** exit code、失敗数、スキップ、未検査の範囲を確認する。
   一部分だけの成功やログの見た目から、全体の合格を推論しない。
5. **証拠が裏付ける範囲だけを報告する。** 試みた作業と検証できた事実を分け、残る不足を明示する。

提出済み報告を検査する場合は、その報告と添付証拠について上の順序・新鮮さ・範囲一致を確かめる。
不足する証拠を後から実行した結果で黙って埋め、元の報告が適合していたことにはしない。
追加確認の結果は、元の報告の不足と区別して新しい検証結果として示す。

## 主張に合う証拠を選ぶ

| 主張 | 必要な証拠 | それだけでは足りないもの |
|---|---|---|
| テストが通る | 対象テストを新規実行した出力と失敗0の確認 | 過去の合格、実行していない見込み |
| linterがクリーン | 対象範囲のlinter出力とエラー0の確認 | 部分チェックを全体へ外挿した説明 |
| ビルドが通る | 対象ビルドコマンドのexit 0 | lint合格、ログの見た目 |
| バグが直った | 元症状の再テスト合格と、関連スコープの回帰なしの証拠 | コードを変更したという事実 |
| 委譲先の作業が完了した | VCS diffなどで実変更を独立確認し、その作業に必要な検証も確認した結果 | 委譲先の「成功」という自己申告 |
| 要件を満たした | 要件・計画を読み直し、一件ずつ証拠と突合したチェックリスト | テストが通ったことからの推論 |

複数種類の主張があれば、それぞれに対応する証拠を確認する。
lintが通ってもビルド成功とはしない。元症状が解消しても、関連する回帰確認の不足を隠さない。
要件被覆の監査そのものが必要な場合は `traceability-audit` へ引き継ぎ、得られた成果物の対象範囲を照合する。

## 確認できない場合

実行できるのに未実行の場合は、必要な確認を実行するまで完了の根拠がないことを示す。
必須の確認が実行不能なら、確認できない対象と理由、必要な手動確認などを明示し、完了・合格として扱わない。
固定の3値コードや、新しい例外承認の仕組みを仮定せず、実際の状態を報告する。

## 照合結果を返す

主張ごとに、対象範囲、実行した確認、出力への参照、exit code・失敗数、
証拠から確認できた事実、スキップ・不足を対応づけて返す。
証拠が足りない主張は不足を列挙し、証拠のある部分と分ける。
報告の適合確認だけで、コード品質、全工程での検証実施、実環境への供給まで完了したとは述べない。

正式判定が求められた場合は、Contract本体と独立したverifierが利用できることを確認する。
利用できなければ自己チェック結果と不足を返し、正式判定は未実施とする。
報告が適合していても、後続操作の権限・承認や工程遷移を自動で成立させない。

## validation（CT-REF-005の報告適合チェック）

各項目を0／5／10で照合する。個別にN/Aとなる項目は分母から除き、充足として加点しない。

| 項目 | 10 | 5 | 0 |
|---|---|---|---|
| INV-01 新鮮な証拠 | 全主張に同一報告内の新規実行出力がある | 一部欠落、または実行時期が不明 | 証拠なし・過去の証拠だけの主張がある |
| INV-02 確認の順序 | 主張特定→確認手段特定→新規実行→出力確認が全件で追える | 一部の手順・対応が追えない | 実行・出力確認の証跡がない |
| INV-03 範囲一致 | 全主張が証拠の範囲と一致する | 範囲が曖昧で一致を確認しきれない | 証拠より広い主張がある |
| INV-04 出力確認 | exit code・失敗数とスキップ・未検査範囲が確認されている | exit codeか失敗数が欠落 | 両方なく、見た目で判断している |
| INV-05 主張別の証拠 | 該当する全主張が必要な証拠を満たす | 一件で不十分な証拠に依存している | 主要な主張が不十分な証拠だけに依存している |
| INV-06 委譲の独立確認 | diffなどで実状態を独立確認した | 独立確認の言及はあるが証拠が不完全 | 委譲先の成功報告をそのまま採用した |
| INV-07 修正の確認 | 元症状の再テスト合格と関連回帰なしの両方がある | 片方だけがある | コード変更だけで修正完了を主張した |
| INV-08 実行不能の明示 | 実行不能な確認を明示し、必要な確認へ引き継いだ | 実行不能への言及はあるが完了判断への影響が不明 | 実行不能を明示せず完了・合格扱いにした |

個別N/Aは次の条件だけで用い、理由を結果に残す。

- INV-05: 対応表に該当する種類の主張が一つもない。
- INV-06: 委譲先の成果報告を完了根拠として扱っていない。
- INV-07: バグ修正完了を主張していない。
- INV-08: 実行不能な検証が発生していない。実行可能だが未実行の検証は、この項目でなくINV-01/02で扱う。

次のいずれか一つでもあればCritical Failとし、対応するINVを0、報告全体を不合格とする。

- DEV-01: 新鮮な証拠のない完了・修正済み・合格の主張。
- DEV-02: 証拠が示す範囲を超える主張。
- DEV-03: 委譲先の成功報告を独立検証せず採用。
- DEV-04: 必須の確認が実行不能なのに、それを明示せず完了・合格扱い。

Critical Failがなければ、適用INVの平均7.0以上をPASS、それ未満を不合格とする。
対象自体が適用外なら採点せず、適用外の理由を返す。対象に主張がある場合のINV-01〜04はN/Aにしない。
