## 概要

`specs/<feature>/requirements.md` の各要件について、受入基準（AC）が正常系だけでなく異常系
（エラー・失敗時の挙動）・境界値（上限/下限・空/最大値等）のパターンを網羅しているかを
検証する。

## 入力

| 項目 | 内容 | 指定例 |
|---|---|---|
| 対象 | 検証する要件 | `specs/<feature>/requirements.md` の各要件AC |
| 網羅カテゴリ | 確認するパターン（既定で正常系・異常系・境界値） | 正常系・異常系・境界値 |

## 手順

1. `対象` の要件ごとに、記述されているAC群を洗い出す。
2. 各要件について `網羅カテゴリ` のうちどれに該当するACが存在するかを分類する。
3. 入力を受け取る・状態を変更する等、異常系や境界値が本質的に想定される要件であるにも
   かかわらず、正常系のACしか無い場合を指摘する。
4. 性質上、異常系や境界値が意味を持たない要件（純粋な表示のみ等）は対象外とする。

## 出力の形

```
{ id, location, finding, is_rollback_candidate }
```

| フィールド | 内容 |
|---|---|
| `id` | この Skill 内で一意な通し番号 |
| `location` | 網羅が不足している要件 |
| `finding` | 不足の事実（例: 「要件1.3は入力必須項目を持つが、未入力時のACが無い」） |
| `is_rollback_candidate` | 通常 `false`（同一フェーズ内でのAC追記で解消できるため） |

## 禁止

- 対象成果物を書き換えない（ACを自動で追記しない）
- 合否を出さない
- 追加すべき具体的なACの文面までは提案しない（不足カテゴリの指摘に留める）
