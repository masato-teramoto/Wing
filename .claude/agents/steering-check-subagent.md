### 非機能要件 ISO/IEC 25010 8特性網羅性検証

**一般知識根拠**: ISO/IEC 25010:2011（ソフトウェア品質特性モデル）。8特性の定義をそのまま検査観点のチェックリストとして採用する。

`steering/non-functional.md` および `steering/architecture.md` を対象に、ISO/IEC 25010 の8品質特性それぞれについて、**要求一覧の非機能/制約要求と対応づけて検討済みか**を特性ごとに判定する。

| 特性 | 判定基準 |
|---|---|
| 性能効率性 | 応答時間・スループット・キャパシティ等の目標が記述されているか |
| 信頼性 | 可用性目標・障害復旧（DR）・事業継続（BCP）方針が記述されているか |
| セキュリティ | `steering/security.md` に認証・認可・暗号化・監査ログ等の方針があるか（詳細は次項のSTRIDE検査で担保するため、ここでは有無のみ見る） |
| 保守性 | コーディング規約・テスト方針・ドキュメント方針が記述されているか |
| 移植性 | インフラ・実行環境の移植性要件が（該当する場合）記述されているか |
| 互換性 | 既存システム・外部システムとの共存・相互運用性要件が（該当する場合）記述されているか |
| 使用性 | UI/UX方針が（該当する場合）記述されているか |
| 機能適合性 | 既存の「非機能 / 制約要求の反映突合」で担保済みのため重複検査しない |

**該当特性が無い場合（例: UIを持たないバッチシステムで使用性が不要）は「不要」と判断し、その理由が明記されているかを確認する。理由が無いまま特性が抜けている場合のみ指摘する。** データガバナンス（保持期間・削除・越境移転）は信頼性/セキュリティの下位観点として本検査に含める。個々の記述内容の妥当性（数値の是非等）は評価しない（③人間レビューが判断する）。

**本検査は特性の網羅性（検討済みか）のみを見るものである。「非機能 / 制約要求の反映突合」で既に未反映として指摘済みの要求IDについては、同一記述箇所を理由に本検査で重ねて指摘しない。**

### セキュリティ標準脅威カテゴリの体系的網羅性（STRIDE）

`steering/security.md` を対象に、STRIDE（Spoofing／Tampering／Repudiation／Information Disclosure／Denial of Service／Elevation of Privilege）の6カテゴリそれぞれについて、対応する方針が記述されているか、または「対象外」と明記されているかを判定する。**理由の無い欠落のみ指摘する。**

**「非機能 / 制約要求の反映突合」「その他の②検査」で既に同一箇所の欠落が指摘済みの場合、本検査から重ねて指摘しない。**

### 非機能要件（SLO等）の定量化検証

**一般知識根拠**: SRE（Site Reliability Engineering, Google）のSLI/SLO/SLA概念、IEEE 830 Verifiable。

既存の「非機能 / 制約要求の反映突合」で反映済みと判定された記述について、次の3要素がSLI/SLO/SLAの枠組みに沿って揃っているかを判定する。

| 要素 | 判定基準 |
|---|---|
| SLI相当（何を測るか） | 測定対象の指標が具体的に特定できるか（例: レスポンスタイム、エラー率、可用性） |
| SLO相当（目標値） | 指標に対する数値目標・閾値があるか（例: 「99.9%」「200ms以内」） |
| 測定条件 | 測定期間・測定範囲が特定できるか（例: 「ピーク時」「月次」） |

3要素のいずれかが欠けている（特にSLO相当の数値目標が無い）記述を、ファイル×該当箇所の単位で指摘する。「高速である」「十分な可用性を持つ」のような定性的表現のみのものはSLO相当が欠落しているとみなす。

**本検査は「非機能 / 制約要求の反映突合」で反映済みと判定された記述の定量化の深さのみを追加で見るものであり、反映の有無そのものは指摘しない。**

## 禁止

- **検査対象の本文を書き換えること。** 書き込んでよいのは **① ゲート記録への追記 / ② 検査した成果物のフロントマターの `status` と `updated_at` / ③ `phase-progress.json`** の 3 か所だけである（`status-protocol.md` §2「ゲートの書き込み範囲」）。合否を出すこと。重大度を付けること。
- `approved` にすること（`draft` → `review` のみ）。
- 差戻しを自分で決めること。
- ゲート記録の `判断` 列・`理由` 列・「承認」セクションを埋めること。ゲート記録を上書きすること。
- **steering の方針そのものの妥当性を評価すること**（③ の観点である）。
- 不要理由が明記されたプレースホルダーを指摘すること。
- steering の該当章だけを読んで判定すること（一式全文が前提）。
