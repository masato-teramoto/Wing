1：Q-DS-PBI-011 の遷移表のほうに合わせてください（007 の「未起案・下書きのときだけ」は取り消し）。
- 削除ボタンは、起案者の番の 未起案・下書き（稟議依頼・修正稟議依頼・再製本依頼とも）と、再製本依頼の 起案済・差戻し で出す。
- 未起案・下書き の削除には条件を付けない（15.1）。
- 再製本依頼の 起案済・差戻し は、その申請No の文書バーコード（TWTGM110）が0件のときだけ削除できる（15.2）。
- 「受付No が NULL のときだけ」の条件は design から外す（未起案・下書きでは受付No は常に NULL のため）。

2：複製の内容に次を足してください。
- 契約局情報（TWTGM140）：元の申請の全行を、新しい申請No で登録する。連番・計画基地局番号ほかの列は元の値のまま。一時保存フラグは "0"。稟議バーコードNo は、再製本では元の値を引き継ぎ、修正稟議では NULL にする。
- 発行依頼書（TWTGM100）：元の申請の行を、新しい申請No で登録する。一時保存フラグは "0"。受付No は、再製本では元の値を引き継ぎ、修正稟議では NULL にする。
- 再製本が元の稟議の稟議バーコードNo を使う（3.7）のは、この TWTGM140 の稟議バーコードNo の引き継ぎで実現する、と書いてください。

3：canOperate の操作に「単独局・複数局の切替」「契約局取込」「契約局DL」「契約局情報追加」を足し、次の条件で判定してください。
- 稟議依頼・修正稟議依頼で、起案者（未起案・下書き、受付済・差戻し）、申請者（受付済・回覧中、受付済・確認中、申請済・差戻し）、確認者（申請済・回覧中、確認済・差戻し）が自分の番のとき。
- 契約局情報追加は、さらに複数局モードのときだけ。
- それ以外（再製本依頼、承認者、番でない人）はボタンを出さず、要求が来たら WTG-100030 で止める。

4：並替え・削除（契約局情報）も 3 と同じ条件に、「複数局モードのとき」を加えて判定してください。canOperate の操作に足し、API の Errors にも書いてください。1行目を並べ替え・削除できない（14.3）はそのまま残します。
（参考：出力ボタンは、複数局モードなら依頼内容・番・状態を問わず全員が使えます）

5：この feature 固有のログ項目はありません。ERROR は既存の ExceptionResolver、INFO は既存の LoggingInterceptor に任せる、と Components と Error Handling に書いてください。担当者の氏名と連絡先をログに出さないことは今のままです。

6：この feature 固有の監視項目はありません（既存の WiNG の監視に任せる）、と Components and Interfaces に書いてください。

7：C。steering の JDK 1.7 は、本番の実行環境とビルドの指定（-source/-target 1.7）を指すものと読みます。開発端末でテストを動かす JDK は、steering の対象外です。steering の追記（開発端末のテスト実行は JDK 1.8 で -source/-target 1.7）は、次に steering を開き直すときにまとめて行います。

8：CsvUtils は、物件基本情報登録変更だけでなく、申請状況一覧（application-status-search）と契約情報ダウンロード（contract-info-download）の CSV 出力でも使う共通部品です。共通基盤（jp.co.kccs.wt.common.utils）に置くのは steering どおりです。design の「本 feature だけで使う」を「複数の feature で使う共通部品。最初に使う本 feature で作る」に直してください。orangesignal-csv も同じ書き方にしてください。

9：URL は steering どおり「/wtg070/<アクション>」の1段にしてください（例：/wtg070/update、/wtg070/shinseIrai、/wtg070/sort、/wtg070/output）。機能ID の後に2段のパスは置きません。文書バーコードのポップアップは、URL 用の機能ID を WTG073 として「/wtg073/<アクション>」にします（steering の規約どおり）。設計判断 4 も、これに合わせて直してください。

10：業務エラーと排他エラーは、例外を投げずに BindingResult に積んで同じ画面に戻してください（steering の「Service の checkXxx で BindingResult.rejectValue にエラーを積む」方式）。
- 状態と操作の組合せ不正：result.reject("WTG-100030", …)
- 排他：既存のキー GEF-000027 を rejectValue で積む
- ApplicationException・ExclusiveException は使わない。予期しない例外だけを ExceptionResolver に任せる。

11：C。依頼内容は、既存の稟議関連の作りに合わせて名称の文字列（"稟議依頼"・"再製本依頼"）で持ちます。steering の型の指針の例外として、次に steering を開き直すときにまとめて追記します。

12：C。判定・権限ID はこの feature の中だけで使う値で、コードマスタを足すと発注者の投入作業が増えるため、DB レイアウトの備考で管理します。連番・SEQ・審査回・通番は、並べ替えや MAX＋1 の計算に使う数値なので Int で持ちます。どちらも steering の例外として、次に steering を開き直すときにまとめて追記します。

13：C。steering の「グループ」は権限区分（TWTZM010.Kengen_Kbn）を指す、と読みます（Q-DS-PBI-009 の回答のとおり）。steering の文言は、次に開き直すときに直します。
