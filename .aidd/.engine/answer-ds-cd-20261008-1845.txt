## Q-DS-CD-002 作業用テーブル
表は `_handoff\work-tables-wtg100.md` に置きました。これを design の正とします。
1. テーブルは 2 つです。
   - `TWTGD050`（発行依頼書リバースデータ）
   - `TWTGD060`（発行依頼書フォーマット）
   - あわせて、ビュー `VWTGM010`（発行依頼書リバースデータビュー）を作ります。
2. 列は次のとおりです。381 列の値をそのまま持つ形で、下書きの「別の案」に近いものです。
   - `TWTGD050`：60 列（実行ユーザーID・データ種別・処理順・計画基地局番号・枝番・項目1〜50・検索条件 4 列・処理順2）
   - `TWTGD060`：実行ユーザーID と、CSV の 381 列
   - どちらも、共通列・主キー・一意キー・索引は持ちません。
3. 使い方は次のとおりです。
   1. 出力のたびに、ログインユーザーの行を両方のテーブルから消します。
   2. `VWTGM010` から `TWTGD050` を作ります。
   3. `TWTGD050` から `TWTGD060` を作ります（基本 → 契約者 → 支払の順に更新）。
   4. `TWTGD060` を並び順で読んで、CSV にします。
   - 行は残し、次の出力のときに消します。
   - 消す・作る・読むは 1 つのトランザクションで行います（読み取り専用にはしません）。
4. 同じ人が 2 つのウインドウで同時に出力した場合は、特に防ぎません。
5. DDL（2 つのテーブルとビュー）は、別表の列定義（列名・型・桁）、「VWTGM010」、「絞り込みと処理順2」をもとに、本 feature の tasks で作ってください。

## Q-DS-CD-008 ボタン・プログラムID・URL・画面を使える人
1. プログラムID・パッケージ・URL は次のとおりです。
   - プログラムID は `PWTGO100` です（`@FuncID("PWTGO100")`）。
   - パッケージは `function/wtg/wtg100` です（`@RequestMapping("/wtg100")`）。
   - URL：
     - `""`（初期表示。GET/POST。パラメータ `FunctionID` と申請No）
     - `search`
     - `page`（パラメータ `selectPage`）
     - `clear`
     - `csv`（出力。`download` ではありません）
   - 物件基本情報登録変更は、`/wtg100?FunctionID=WTG100` に申請No を足して、ポップアップで開きます。

3. 出力の後も、画面はそのままです（検索結果と選択を残します）。
   - 未選択でエラーのときは、検索結果を残したまま同じ画面にエラーを出し、CSV は返しません。

   - 投入の文と手順は本 feature の tasks で作り、投入は発注者が導入手順書に沿って行います（7 の 3 と同じ）。

## Q-DS-CD-009 受け取った申請No の扱い
1. はい。
