上流はそのままにして、申請No も採番マスタ（TWTZM050）と既存の NumberingService で採番してください。
前の回答（TWTGM080 の最大値＋1、上限の処理を設けない）は取り消します。

採番マスタに足す行：
| 列 | 値 |
|---|---|
| グループID（Grp_Id） | WTG070 |
| 識別コード（Shikibetsu_Cd） | 01 |
| プレフィックス（Prefix） | 空（"B"＋YYMMDD はプログラムで付ける） |
| 最小値 | 1 |
| 現在値 | 0 |
| 最大値 | 9999 |
| 採番区分 | 02（日次リセット） |
| MAX区分 | 1（ローテーションなし） |
| 備考 | 申請No |

- 申請No ＝ "B" ＋ YYMMDD（システム日付）＋ 取得した値を4桁の0埋めにしたもの。
- MAX区分は、DB レイアウトでは「0：ローテーションあり／1：ローテーションなし」です。0 は「上限を超えたらエラー」ではないので注意してください。上限を超えたときに 0001 へ戻って既存の申請No と重なるのを避けるため、1 にします。上限を超えたときの動きは NumberingService の既存の動きに従います（requirements 1.5 のとおり）。
- 採番は業務とは別の接続で確定させる（steering のとおり）ので、同時に登録しても番号は重なりません。同時登録の扱いを別に決める必要はありません。
