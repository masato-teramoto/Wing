Q-DS-PBI-007（文書バーコード TWTGM110 とポップアップ）

Q-DS-PBI-007 に回答します。

■ 1. 列（TWTGM110 契約文書情報マスタ）
| 論理名 | 列名 | 型 | 桁 |
|---|---|---|---|
| 稟議バーコードNo | Ringi_Barcode_No | String | 25（必須） |
| 文書バーコードNo | Doc_Barcode_No | String | 25（必須） |
| 削除フラグ | Delete_Flg | String | 1（0:未削除 1:削除） |
| 書類種別コード | Doc_Kind_Cd | String | 20 |
| 件数 | Count | String | 3 |
| 文書名 | Doc_Name | String | 256 |
| コメント | Doc_Comment | String | 256 |
| 申請No | Application_No | String | 11 |
ほかに共通列（会社コード・登録者・登録日時・更新者・更新日時・排他フラグ）。主キーは定義せず、一意キーは 会社コード＋稟議バーコードNo＋文書バーコードNo です。

- 画面の「有効/無効」は削除フラグで表します。行は物理削除せず、「更新」ボタンで有効/無効にチェックを付けた行の削除フラグを反転します（0→1、1→0）。コメントは、変更があった行だけを更新します。
- 件数（連番）は、同じ稟議バーコードNo・書類種別コードの MAX(件数)＋1 です。列は文字列なので、比べるときは数値に変換します。
- 文書名は将来のために列だけ作ります。今回は値を入れません。
- 一覧の並びは、書類種別コードの昇順、件数（数値）の昇順です。書類名は P33 の名称を出します。
- コメントの入力は最大256桁です。

■ 2. 値の各部品の出どころ
文書バーコードNo ＝ 基地局番号 ＋ "-" ＋ エリア接頭語 ＋ 受付No ＋ "-" ＋ 契約区分 ＋ 書類種別コード ＋ 件数
- 基地局番号：契約局情報欄で押した行（TWTGM140）の基地局番号です。物件申請情報の基地局番号ではありません。稟議バーコードNo のリンクから、その行の基地局番号を渡します。
- エリア接頭語：発行依頼書の担当エリア（TWTGM100.Area_Cd）をキー3にして、コードマスタ WTG/PARAM/P34 を引いた文字項目1。
- 受付No：TWTGM100.Uketsuke_No。
- 契約区分：TWTGM100.Keiyaku_Kbn をキー3にして、コードマスタ WTG/PARAM/P78 を引いた文字項目2。
- 書類種別コード：画面で選んだ P33 のコード。生成の前に P33 に存在するかを確かめ、無ければ WTG-000072「ｺｰﾄﾞﾏｽﾀに登録されていません」で止めます。
- 発行依頼書は申請No で引きます。

ポップアップへ渡す値は、稟議バーコードNo・申請No・基地局番号・受付No・依頼内容です。

■ 3. 生成の操作
書類種別を1つ選んで「文書バーコード生成」を押すと、1件生成して一覧に1行追加します。まとめて生成はしません。

■ 4. 11.8 の意味
そのとおりです。再製本は元の稟議と稟議バーコードNo が同じです。その稟議バーコードNo で生成済み（削除フラグ＝0）の書類種別だけを、プルダウンに出します。稟議依頼・修正稟議では、P33 の全件を表示順に出します。

■ 5. 申請の削除と文書バーコード
文書バーコードの行は消しません。そのかわり、申請を削除できる条件で絞ります。
- 稟議・修正稟議：発行依頼書の受付No が未発番（NULL）のときだけ削除できます。受付No が無いと文書バーコードは作れないので、消す行はありません。
- 再製本：その申請No の文書バーコードが0件のときだけ削除できます。
- 削除ボタン自体は、起案者の番の 未起案・下書き のときだけ出します。

■ 6. 「発番後」「発番済み」の判定
- 文書バーコード生成（11.2）：発行依頼書の受付No が NULL でないことで判定します。受付No は文書バーコードNo の部品です。
- 閲覧・印刷（6.9）の「発番済」：印刷・閲覧用帳票の design と同じく、ステータスが受付済（02）以降であることで判定します。発番では受付No の採番とステータス 02 への更新を同時に行うので、どちらで見ても結果は同じです。

■ 補足（稟議バーコードNo リンクを使える人）
稟議バーコードNo のリンク（文書バーコード生成を開く）は、発番後に申請者・確認者だけが使えます。それ以外の人と、発番前はラベルで表示します。
