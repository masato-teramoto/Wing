Q-DS-PBI-012（下流の feature が持つ定義を使うところ）

A でお願いします。列名と CSV の形をここで決め、物件基本情報登録変更の design に「この形で読む・出す」と書いてください。発行依頼書登録変更・契約情報取込の design はこれに合わせます（再確認が必要になる条件に入れてください）。

■ 1. 発行依頼書（TWTGM100）の列
申請No（Application_No）と 1 対 1 です（一意キー 会社コード＋申請No）。
| 使う箇所 | 論理名 | 列名 | 型・桁 |
|---|---|---|---|
| 12.1 の会社名 | 契約稟議起案者_会社名 | Keiyaku_Ringi_Kiansha_Kaisha_Name | String 50 |
| 6.5 | 契約稟議起案者_会社コード | Keiyaku_Ringi_Kiansha_Kaisha_Cd | String 20 |
| 7.3・14.6 | 受付No | Uketsuke_No | String 6 |
| 14.6 | 契約区分 | Keiyaku_Kbn | String 20 |
| 14.6 | 担当エリア | Area_Cd | String 20 |
| 14.6 | 申請者 | Application_Name | String 100 |
| 14.6 | 契約稟議起案者_所属名① | Keiyaku_Ringi_Kiansha_Shozoku1 | String 100 |
| 14.6 | 契約稟議起案者_所属名② | Keiyaku_Ringi_Kiansha_Shozoku2 | String 100 |
| 14.6 | 契約稟議起案者_氏名 | Keiyaku_Ringi_Kiansha_Name | String 100 |

- 稟議バーコードNo は TWTGM100 にはありません。契約局情報（TWTGM140）の Ringi_Barcode_No（String 25）で、契約局の行ごとに持ちます。7.3 で「稟議バーコードNo」と言っているのは TWTGM140 の列です。

■ 2. 9.1 の CSV の形（契約局取込で読める形）
- 1行目：発行依頼書（TWTGM100）の1行を 188 項目で出す。先頭は受付No。
- 2行目以降：契約局情報（TWTGM140）を連番の順に1行ずつ、228 項目で出す。先頭は稟議バーコードNo、最後は添付資料(補足)⑤。
- 見出し行はありません。1行目からデータです。
- コード値の一部は名称に変換して出します（例：関係者の関係(地位)は P45 の名称、法人個人区分は P06 の名称、郵便番号から住所マスタ ZM400 の住所）。各項目の並びと出し方は、契約局取込が読む項目の並びと同じです。
- requirements の「229列」は、この「1行目 188 項目、2行目以降 228 項目」の形に読み替えてください。
- 項目ごとの一覧（416 行）は量が多いので、design には上の形と「契約情報取込の取込レイアウトと同じ並び」だけを書き、一覧は実装（Phase 8）で渡します。
