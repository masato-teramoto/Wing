Q-DS-PBI-005 その1（承認履歴 TWTGM180 の列と登録の規則）

■ 1. 列（TWTGM180 物件申請情報承認履歴マスタ）
| 論理名 | 列名 | 型 | 桁 |
|---|---|---|---|
| 申請No | Application_No | String | 11（必須） |
| 審査回 | Shinsa_Count | Int | 5（必須） |
| 通番 | Tsuban | Int | 5（必須） |
| 最終更新日 | Last_UpdatedDT | DateTime | - |
| 最終更新者 | Last_UpdatedPerson | String | 20 |
| コメント | Hantei_Comment | String | 1000 |
| 判定 | Hantei | String | 2 |
| 審査権限 | Shinsa_Kengen | String | 10 |
| 最終更新者名 | Last_UpdatedPerson_Name | String | 20 |
ほかに共通列（会社コード・登録者・登録日時・更新者・更新日時・排他フラグ）。一意キーは 会社コード＋申請No＋審査回＋通番。

- 審査フェーズと状態は持ちません（物件申請情報の Status・JOTAI_KBN だけで持つ）。
- 行は、回覧の操作（申請依頼・確認・承認・申請・差戻・取下）のたびに1行 INSERT します。物件申請情報を更新した後に登録します。
- 審査回：物件申請情報を更新した後の申請回数（申請依頼では +1 した後の値）。
- 通番：同じ申請No・審査回の MAX(通番)+1。まだ行が無ければ 1。
- 最終更新日＝システム日時、最終更新者＝ログインユーザーID、最終更新者名＝ログインユーザー名。
- 審査権限：操作した人の権限。コードマスタ WTG/PARAM/P82（01 起案者・02 申請者・03 確認者・04 承認者）。
  - 申請依頼＝01、確認＝02 か 03（申請者が押したら02、確認者が押したら03）、承認＝04、申請＝02
  - 差戻＝押した人に応じて 02・03・04、取下＝押した人に応じて 01・02・03
- 申請の削除では、その申請No の承認履歴を物理削除します。
