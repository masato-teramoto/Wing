# API 設計標準

> このファイルは、**全 API に共通する形**（命名・URL の組み立て方・リクエストとレスポンスの形式・ステータスコード・認証ヘッダ・バージョン管理・エラー表現）を確定させる文書である。\
> _分担_: 個別の API 定義は `specs/<feature>/design.md` の `##### API 契約（API Contract）` に、このファイルとの違いだけを書く。エラーボディのフィールド定義は本ファイルの `## エラーハンドリング（API 契約）`、認証ヘッダと権限の判定は `security.md` の `## 認証・認可`、ページネーションの DB 側の方針は `database.md` の `## クエリパターン` を正とする。

> _書き方_: 全 API に共通する形だけを書く。エンドポイントの一覧はここに書かない。

> _本プロジェクトでの扱い_: 画面以外から呼ばれる API を設けないため、全節を不要とする（回答 7）。既存 wing で JSON を返すのは画面内のプルダウン取得の 2 か所だけで、外部公開 API は無い（`wing/src/main/java/jp/co/kccs/wt/function/wte/wte020/controller/Pwteo020Dialog2Controller.java`）。

## HTTP メソッド

> 使う HTTP メソッドごとに、用途と性質を確定させる節。ここで決めた性質が、再実行やキャッシュを設計するときの根拠になる。\
> _分担_: 失敗したときに再実行してよいかの判断は `non-functional.md` の `### リトライ`。ここにはメソッドの性質だけを書く。

> _書き方_: このプロジェクトで使うメソッドだけを書く。冪等性には、同じ要求を何回送っても結果が変わらないかを書く。安全性には、サーバ側の状態を変えないかを書く。

| メソッド | 用途 | 冪等性 | 安全性 |
|---|---|---|---|
| <HTTP_METHOD_N> | <HTTP_METHOD_USAGE_N> | <HTTP_METHOD_IDEMPOTENT_N> | <HTTP_METHOD_SAFE_N>（不要：画面以外から呼ばれる API を設けない — 回答 7） |

> _書き方_: 一番外側のキーの構造を書く。成功とエラーでキーを分け、**成功レスポンスに `error` を含めない**。

## 認証情報

> 認証情報の渡し方と、処理を行う順序を確定させる節。誰であるかを確かめ、何をしてよいかを判定し、その後で業務ロジックへ進む。\
> _分担_: 認証ヘッダの仕様と権限判定の詳しいしくみは `security.md` の `## 認証・認可`。ここには API としての受け渡し方だけを書く。

> _書き方_: 標準位置には、どのヘッダにどの形式で載せるかを書く。未認証時の扱いには、返すステータスコードと、理由をどこまで伝えるかを書く。認可の方針には、どの層で権限を確かめ、どこから先を `security.md` に委ねるかを書く。

- 認証情報の標準位置: <AUTH_HEADER_STANDARD>（不要：画面以外から呼ばれる API を設けない — 回答 7）
- 未認証時の扱い: <AUTH_REJECT_POLICY>（不要：画面以外から呼ばれる API を設けない — 回答 7）
- 認可（権限チェック）の方針: <AUTHZ_DEFENSE_POLICY>（不要：画面以外から呼ばれる API を設けない — 回答 7）
